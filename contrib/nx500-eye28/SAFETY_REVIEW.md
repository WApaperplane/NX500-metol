# EYE28 → metol：离线安全审查

日期：2026-11-27。编码按用户要求由 GPT-6.1 Terra 执行，主代理复核源码、构建及故障用例。本记录只覆盖电脑端离线产物。本轮没有连接相机、修改存储卡、安装服务或启动快启重建。

## 发布结论

这是开发审查包，设备启用保持关闭。默认 ARM helper 无论传入什么参数都输出 `NATIVE`；只有另行编译的 TEST_BUILD 能在 `/tmp/` 下的隔离假根运行验证和发布测试 token。测试二进制不进入交付包。包内没有安装器、自动触发文件、服务或镜像写入程序。

此状态不能表示“已可安装”或“保证不会变砖”。可信镜像证明的生产者、实际制作快照前的预加载接线及 OEM 写入事务尚未实现。本次不复用先前相机重建流程。

## 已核实的算法身份

- 来源固定为上游提交 `eafc274e0ef0b6cb95b5ad958b2f1ac86dfc3562` 中 `release/0.4.0/eye-af`，保留 AGPL-3.0-only 许可证。
- 三个算法源文件与四个回放文件逐字节校验一致。构建库 SHA-256 为 `e167e84a6be88b2fc21da13a5952a923ec7a032cb37612a11e047e60dc6c2e6e`，与原始版本一致。
- ARM 回放：57 个固定场景匹配；90 帧稳定序列均为眼部结果，临时全脸暴露为 0。这是合成回放，不是实拍表现或暗光性能证明。
- 库为 ELF32 ARM EABI5 soft-float；仅导出原有 FaceDetection 拦截符号，版本化动态符号需求为 GLIBC_2.4。

## 适配层的验证边界

真实 native 测试读取的是假根中的 proc stat、boot ID、maps、swap 表、证明和文件。文件摘要通过固定路径工具、固定 argv 及已打开的文件描述符计算；不使用 shell 执行文件名。生产 helper 不依赖相机安装 Python。

启动选择与恢复分开：执行前选择不能要求目标 App 已存在于进程映射；恢复才检查 PID、starttime、exe、文件摘要和可执行映射的设备号/ inode。恢复发布测试 token 前反复复核状态，旧 token 需要同一 generation、starttime 和 inode 的 sidecar 才能视为重复请求。

所有 fixture 证明仍是测试输入。代次字段一致、文件哈希匹配及主机测试通过，均不能替代机身镜像头和写入报告的可信采集。`profile.json` 内的机身依赖哈希是历史参考，不是恢复后机身的新测量。

`metol/workflow.py` 及 `tests/models/` 是资源交接模型，用于回放“准备拒绝不碰资源、写头前拒绝仅撤回本轮资源并发布 ready”的顺序。它们没有接入 OEM writer，不能证明实机 `.hib_ready` 已可靠交接。

## 仍需通过的设备门禁

1. 只读核实恢复后 App、T2、libcapture、libface 和符号/布局。EYE28 使用 NX500 1.12 的固定结构偏移；修改显示版本号不能证明二进制兼容。
2. 实现并单独审查实际镜像头、快照代次及写入报告的可信关联；确保启动选择失败时保留原厂入口，准备失败不阻断原厂 readiness。
3. 实现制作快照前的预加载接线和资源所有权回退；蓝牙后置入口不能给已初始化的 App 补上预加载。真实安装、卸载及旧快照处理尚未完成。
4. 核实可用备份和恢复路径，再进行受控的真实快启、休眠/唤醒、半按/全按、拍照/视频及暗光测试。不得以本包作为刷写或重建指令。

原算法有两项需要特别保留的限制：`RTLD_NEXT` 原厂 FaceDetection 绑定失败会返回 `-1`，不能声称所有加载失败都会自动回到原厂；PID token 本身没有代次字段，sidecar 也不由原库读取。生产启用前必须解决旧快照与 PID 复用的生命周期管理。多次用户态复核无法提供内核级原子保证，也不能撤回已被另一个线程读取的 token。
