## 11-28 re-release: two boot popups removed (subtraction only)

### Symptom

After Bluetooth initialisation (or any boot) the camera shows a `rc: 192.168.x.x` strip for
4 seconds, then a window titled **NX-MOD GUI** with `REMOTE:` / `USER:` / `PASS:` — all
`not entered` if nx-netfs was never installed.

### Root cause

mod_gui's checkbox semantics are "tick it → copy the script into `auto/`, keyscan runs
everything in `auto/` at startup", so two ticked entries became two autostarts:

| Window | Checkbox | Autostart file | Emitted by |
|---|---|---|---|
| `rc: <IP>` | Remote Ctr | `auto/nx-rc.sh` → `nx-rc.sh` | its IP-hint function, `onscreen_rc "rc: $IP"` for 4 s |
| NX-MOD GUI config | Remote Save | `auto/rem.sh` → `rem.sh` | `rem_gui` (same title template as mod_gui) |

The 11-22 commit also pulled the camera's own `scripts/auto/rem.sh` into the repo, so every
fresh install had "Remote Save" enabled by default — a config window nobody could fill in.

### What changed

1. **`scripts/auto/rem.sh` deleted**, plus an idempotent cleanup in `install.sh`:
   `rm -f /opt/usr/nx-ks/auto/rem.sh` + `killall -q rem_gui`. This is the only exception to
   install.sh's "overwrite, never delete" rule, and it runs *after* `cp -ar` — otherwise the
   old copy on the SD-card master would come back.
2. **"Remote Save" entry removed from the Custom Func. page** (`gui_func.NX500`, `.NX1`, and
   the EN overlay copy). Ticking it again regenerates `auto/rem.sh` as before.
3. **Boot IP hint removed from `nx-rc.sh`.** The proper place is unchanged: the main menu row
   `IP: 192.168.x.x [SSH on]`.

The classic `mod_gui` fallback menu stays (added in 1.15.10) and no longer pops up on its own.

## Who needs this

**Anyone running the EN package.** In 1.15.8 and 1.15.9 the EN build cannot open the
panel on a double press of EV — so no menu, and no way to reach Uninstall. The CN
package is unaffected, but this release adds the same safety net to both.

## Root cause

The English panel binary `nxui_en.arm` was frozen at the 11-14 build and never
rebuilt afterwards.

- Since 11-20 the launcher `nxui.sh` installs both layers (LUT + FilmLab) at once and
  therefore passes three extra options: `--lut-recipes`, `--lut-engine`,
  `--lut-recipes-vlog`.
- The old EN panel does not know those options, falls through to `else`, prints one
  `Usage:` line and returns 2.
- `nxui.sh` starts the panel in the background and exits 0 either way — so from the
  outside it looked like a success while no window was ever created.

Effect: double-pressing EV does nothing, EV+WiFi does nothing, and the menu — with the
only Uninstall entry — is unreachable. The CN package ships the current binary, which
accepts those options, so only the EN package was hit.

## What changed

1. **EN panel rebuilt** from the current `nxui.c`, same generation as the CN one.
   It also picks up 11 strings added after 11-20, and with them the new 292 px menu,
   in-panel banners, multi-line dialog and the LUT / FilmLab tabs.
2. **Packaging gate**: before building the EN zip, `pack_release.py` now checks that the
   panel binary knows every option the launcher passes and is newer than the sources.
   If not, the zip is not built. No more "the file exists, ship it".
3. **Double-press fallback**: if the panel has not appeared within one second, the
   classic popup (`mod_gui`) is started instead. If the panel ever breaks again, the
   menu and the Uninstall entry stay reachable.

### 11-28 on-device recheck: the fallback was one layer short (fixed)

Replacing `nxui.arm` with a fake panel that execs fine and then `exit 2` after 250 ms:
the 400 ms liveness window in `EV_EV.sh` correctly ruled it a failure
(`pid 1446 → none`) and called `classic` — **but `mod_gui` never came up**.

Cause: `loadgui.sh` prefers nxui too —

```bash
if [ -x /opt/usr/nx-ks/nxui.sh ] && /opt/usr/nx-ks/nxui.sh available; then
    /opt/usr/nx-ks/nxui.sh menu
    exit $?
fi
```

and `nxui.sh available` only checks "binary exists + executable + model + no
`disabled` marker". A broken binary passes. So `classic` → `loadgui` relaunched the
same broken panel and `mod_gui` was never reached. The verdict was right; the exit
route was not.

Fix: `loadgui.sh` takes `NXUI_FALLBACK=1` (skip the nxui branch, keep the
prefman / DIALMODE / gen_menu preparation, go straight to `mod_gui`); `EV_EV.sh`
`classic()` sets it. Recheck: `pid 1446 → none`, `mod_gui_after=running`,
`nxui.arm` restored to md5 `efbe7a86`.

## If you are locked out right now

No SSH and no menu needed: copy the three files from `uninstall_pkg/` in the zip
(`info.tg`, `nx_cs.adj`, `uninstall_direct.sh`) to the SD card root, insert the card —
the camera uninstalls and reboots by itself.

Then install the 1.15.10 EN package.

## Install

Same as always: unpack `Metol-1.15.10.zip` (or `-EN`) to the SD card root → insert the
card → wait for the on-screen confirmation → the camera reboots.

**Note**: `cp -ar` overwrites but never deletes, and the `scripts/` folder on the SD
card is the master copy. When updating by hand, copy the new files into that folder,
otherwise the next install will put the old version back.

## The Log117 gamma engine now ships in the package (V-Log works out of the box)

Before 1.15.10 the V-Log curve needed a separately installed engine; without it the menu item
only reported "missing". The closure is now part of the release:

| Item | Value |
|---|---|
| Location | `metol-extensions/log117/` inside the zip (SD-card root after extraction) |
| Contents | 32 files, 1.3 MB: `gamma-reload.sh`, 15 `nxl-*.arm`, `data/clean-log/`, `payload.sha256` |
| Identity | Unified R1 `eafc274`, `payload.sha256` pinned to `a30ad550a68653d475aee8201e20dfbd16fd91802f2f5a41ea2e49c60fdcbf6f` |
| Install behaviour | after syncing `scripts/`, `install.sh` runs `gamma-log117-install.sh install`: **installs but never activates**, the previous gamma tree is moved aside as `gamma-before-log117-<stamp>-<pid>`, runtime `state/` is preserved, idempotent |
| Manual | `sh /opt/usr/nx-ks/gamma-log117-install.sh check` / `install`, log at `/tmp/nx-ks-gamma.log` |
| Size | about 0.8 MB added to each zip |

> Installed ≠ enabled. V-Log is still toggled with **EV + AEL** or the menu, and it refuses unless
> A18 is back to stock (`lut.sh off`), PW is neutral and no USB is attached — details in
> `/tmp/nx-p0/vlog-gate.log`. Conversely, shipping the engine never changes the running state:
> `vlog.sh off` or a reboot returns to the stock gamma.

## Emergency recovery: unbrick without disassembly (documented in this release)

If the camera no longer boots (`nx-on-wake` gone wrong, `systemctl rescue`, damaged system or
hibernation state), you do **not** need disassembly, motherboard shorting, UART, or
`downloader.bin`:

1. Extract an official, **unmodified** `nx500.bin` (e.g. v1.12) to the root of a clean **FAT32** SD card
2. Remove the battery → insert the card → flip the rear display **fully up into the selfie position** → reinsert the battery (power OFF)
3. Hold **MOBILE(Wi-Fi) + AEL + full Shutter** together, then switch the camera **ON**
4. When the blue `Recovery Mode` screen appears (`F/W Check` / `Update` / `Update Finish`), release and **hold the shutter** as prompted to flash

Never cut power or pull the battery while flashing, until `Update Finish`; official firmware only.
Verified end-to-end on a soft-bricked NX500, **not verified on the NX1** (different GPIOs, no
flip-up screen). Details:
[`BOOT0_ANATOMY.md`](https://github.com/WApaperplane/nx500-dnloader/blob/main/docs/BOOT0_ANATOMY.md)
(`GPIO_WIFI_KEY` 19 / `GPIO_SHUTTER_KEY2` 27 / `GPIO_FLIPUP_INT` 30 / `GPIO_AEL_KEY` 31).

> Flashing only rewrites the system partitions; **p14, which holds `/opt/usr/nx-ks`, is
> untouched** — insert the SD card afterwards and one incremental sync brings the mod back.
> Whether the p9 hibernation snapshot survives a flash has **not** been verified, so run the
> read-only probe before reinstalling rather than assuming.
