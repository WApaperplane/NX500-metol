# Metol 1.15.10

> 2026-11-27 · EN package fixed: no more "installed, but EV does nothing"

## Who needs this

**Anyone running the EN package.** In 1.15.8 and 1.15.9 the EN build cannot open the
panel on a double press of EV — so no menu, and no way to reach Uninstall. The CN
package is unaffected, but this release adds the same safety net to both.

## Root cause

The English panel binary `nxui_en.arm` was frozen at the 11-14 build and never
rebuilt afterwards.

- Since 11-20 the launcher `nxui.sh` installs both layers (LUT + FilmLab) at once and
  therefore passes three extra options: `--lut-recipes`, `--lut-engine`,
  `--lut-recipes-vlog`.
- The old EN panel does not know those options, falls through to `else`, prints one
  `Usage:` line and returns 2.
- `nxui.sh` starts the panel in the background and exits 0 either way — so from the
  outside it looked like a success while no window was ever created.

Effect: double-pressing EV does nothing, EV+WiFi does nothing, and the menu — with the
only Uninstall entry — is unreachable. The CN package ships the current binary, which
accepts those options, so only the EN package was hit.

## What changed

1. **EN panel rebuilt** from the current `nxui.c`, same generation as the CN one.
   It also picks up 11 strings added after 11-20, and with them the new 292 px menu,
   in-panel banners, multi-line dialog and the LUT / FilmLab tabs.
2. **Packaging gate**: before building the EN zip, `pack_release.py` now checks that the
   panel binary knows every option the launcher passes and is newer than the sources.
   If not, the zip is not built. No more "the file exists, ship it".
3. **Double-press fallback**: if the panel has not appeared within one second, the
   classic popup (`mod_gui`) is started instead. If the panel ever breaks again, the
   menu and the Uninstall entry stay reachable.

### 11-28 on-device recheck: the fallback was one layer short (fixed)

Replacing `nxui.arm` with a fake panel that execs fine and then `exit 2` after 250 ms:
the 400 ms liveness window in `EV_EV.sh` correctly ruled it a failure
(`pid 1446 → none`) and called `classic` — **but `mod_gui` never came up**.

Cause: `loadgui.sh` prefers nxui too —

```bash
if [ -x /opt/usr/nx-ks/nxui.sh ] && /opt/usr/nx-ks/nxui.sh available; then
    /opt/usr/nx-ks/nxui.sh menu
    exit $?
fi
```

and `nxui.sh available` only checks "binary exists + executable + model + no
`disabled` marker". A broken binary passes. So `classic` → `loadgui` relaunched the
same broken panel and `mod_gui` was never reached. The verdict was right; the exit
route was not.

Fix: `loadgui.sh` takes `NXUI_FALLBACK=1` (skip the nxui branch, keep the
prefman / DIALMODE / gen_menu preparation, go straight to `mod_gui`); `EV_EV.sh`
`classic()` sets it. Recheck: `pid 1446 → none`, `mod_gui_after=running`,
`nxui.arm` restored to md5 `efbe7a86`.

## If you are locked out right now

No SSH and no menu needed: copy the three files from `uninstall_pkg/` in the zip
(`info.tg`, `nx_cs.adj`, `uninstall_direct.sh`) to the SD card root, insert the card —
the camera uninstalls and reboots by itself.

Then install the 1.15.10 EN package.

## Install

Same as always: unpack `Metol-1.15.10.zip` (or `-EN`) to the SD card root → insert the
card → wait for the on-screen confirmation → the camera reboots.

**Note**: `cp -ar` overwrites but never deletes, and the `scripts/` folder on the SD
card is the master copy. When updating by hand, copy the new files into that folder,
otherwise the next install will put the old version back.
