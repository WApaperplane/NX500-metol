# Metol 1.15.8

发布日期：2026-11-22

这一版主要一件事：**FilmLab 从点配方到画面变化，790 ms 降到 510 ms**。

## 1. 预览快了 35%

之前一次预览的分段是：确认实际档位 380 ms + 发送七维 400 ms。

发送那 400 ms 拆开看，真正的 MCB 写入只有 **0.4 ms** —— 8 条 `SetVariableDataMCB`
在一个进程里依次发完就是这个数。剩下的是 820 KB（-O0）二进制的加载约 60 ms、
`libcapture-fw-prod` 的 `dlopen` 73 ms、条间 7×20 ms 的固定间隔 142 ms、收尾 100 ms。

后两段是 A1 时代留下的保守值，实测都不必要：

- 去掉条间间隔后，七维全改（112/111/108 12/8/9/10）用 `varlist` 读回是
  R/G/B=111/111/107 HUE=12 SAT=8 SHARP=9 CON=10，七维全部落地、末条提交位也生效，
  而 prefman slot9 全程没有被写；发回原值后逐维复现基线。
- 收尾那 100 ms 是给「读回」留的。预览发完就退出，读回本来由 `filmlab.sh check`
  单独做。

新工具 `pwfast` 是 3.3 KB 的 `-nostdlib` 程序，只依赖 `libdl.so.2`，一次 68 ms。
`filmlab.sh` 优先走它，文件不在时逐字回退到原来的 `pwsend seq`。

## 2. 一个会写坏自定义槽的隐患

上一版为了省一次读档位，加过一个 90 秒缓存。问题在于标记只记了时间、没绑定
「当前在哪一档」：用户在自定义1 预览过，用物理拨盘切到自定义2，90 秒内再点配方，
提交位就把七维写进了自定义2 —— 而脚本只备份过 slot 9，那一档救不回来。

这版撤回缓存，每次都真读档位。代价是那 380 ms 回来了，换来的是任何档位都不会被误写。

## 3. 相册

- **缩略图预热默认关停**。NX500 原片自带 320 px（IFD1）/ 1616 px（MPF）内嵌图，
  直切字节就够；预热跑 62 张的实际结果是 `generated=0 sliced=62`，纯空转，还白占
  单核 CPU 与 SD 读。需要时（导入外机照片 / PNG）可手动跑。
- **并发请求不再互相踩**：在飞请求改用票据表，目录切换有代际号，晚到的回调按代际
  丢弃；超并发改为排队；收起面板时取消排队中的请求，不再出现「点开没内容、等
  一下又冒出来」。

## 4. 顺手的修复

- `capdtm-httpd stop` 原先先 `killall busybox`，会连带杀掉所有 comm=busybox 的
  进程（含 telnetd），后面才是精确过滤。前一句多余且自杀，已删。
- LUT 换表加了 `NX_TIMING` 分段计时（默认零开销），用来判断「首次启用与后续换表
  能不能拆开」。

## 已知限制

预览剩下的 510 ms 里有 380 ms 是一次 `st cap capdtm getusr 20`。它慢不是因为读档位
本身，而是 `st` 链了 83 个共享库 —— `time` 显示 user 0.29 s / sys 0.02 s，纯 CPU
加载。绕开它需要逆 CAP DTM 的实现，本轮试了三条路（System V 消息队列 / prefman 键 /
全盘字符串定位）全部证伪，短期内不会再碰。
