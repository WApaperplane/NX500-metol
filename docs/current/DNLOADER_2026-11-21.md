> 素材来源：`jaecktec/nx300-source`（GitHub，NX300 完整 GPL 源码树）中的

> 并据此搞清 NX500 版需要改什么、卡在哪。**NX500 版尚未产出。**

---

## 0. 一句话

dnloader 不是"另一个程序"，而是 **同一份 bootloader 源码加 `-DCONFIG_DNLOADER` 编出来的裸二进制**；
它不自己刷整片，只做三件事：**把 SD 上的 SLP 搬进 DDR → 擦引导块 → 写镜像信息设参数**，
剩下的交给 SLP 里的 flasher。

---

## 1. 它是什么（构建证据）

`Makefile.dnloader`：

```make
TARGET := $(BUILD_TOP)/dnloader.bin
LINKER := $(SOURCE_TOP)/dnloader.ld
ASFLAGS := -g -mthumb-interwork -mcpu=cortex-a9
CCFLAGS := -Os -g -mno-thumb-interwork -mcpu=cortex-a9 -Wall
CCFLAGS += -ffreestanding -nostdlib -fno-builtin -static
DEFS    := -DCONFIG_DNLOADER -DDEBUG -DARM_800Mhz -DCONFIG_PROJECT_NX300
OBJCOPYFLAGS := -x -S --output-target binary
```

`dnloader.ld`：

```
ENTRY(_start)
SECTIONS { . = 0x70200000; ... }
```

`OBJS` 里有 **`drv/sdmmc/sd_api.o` + `drv/sdmmc/sd_cmd.o` + `FatFs/tff.o`** ——
**SD 卡驱动 + FAT 文件系统**，这就是它能读 SD 卡根目录那个 `.bin` 的原因。
（对比：NX500 的 `boot0.bin` 里 **零个** "SD" 字符串，只认 eMMC。）

**产物形态**：裸二进制、无头无校验、首字节即向量表
`06 00 00 ea`（`b +0x18` → 0x20）。
★ 与 NX500 的 `boot0.bin` 首字节 `07 00 00 ea`（`b +0x1C` → **同一个 0x20**）同构。
⇒ 两者是同一类东西，bootROM/SBL 用同一种方式加载。

## 2. 它干什么（`usr/Main.c` 的 `do_dnloader`）

```c
static inline u32 do_dnloader(void)
{
    /* ① 板子自检：读 GPIO 0x300503fc bit4，不是 NX300 就死循环 */
    unsigned int filp_gpio = (*(volatile unsigned int *)(0x300503fc)) & (1 << 4);
    if (filp_gpio != 0) { Uart_Printf("this is not nx300 board exit\n"); while (1); }

    Uart_Printf("> Checked Device\n");
    InitFs();                       /* ② FatFs 挂 SD */

    /* ③ 清零 ImgInfo，但保留 D4 e-Fuse 段 */
    for (cnt = 0; cnt < WINFO_D4_EFUSE_TYPE; cnt++) ImgInfo[cnt] = 0;
    ImgInfo[WINFO_NUM_BBLK] = FLASH_numBadBlk;      /* ④ 存坏块表 */
    for (cnt = 0; cnt < FLASH_numBadBlk; cnt++)
        ImgInfo[WINFO_BADLIST + cnt] = FLASH_BadList[cnt];

    /* ⑤ 主路径：把 SLP 整包搬进 DDR */
    if (CopyFwfsImage2DDR(SLP_FW_NAME, 0xc0007fc0, 0xa00000) == 0)
    {
        nand_EraseBlocks(0, 1);                     /* 擦第 0 块（引导信息） */
        nand_setImgInfo(ImgInfo, sizeof(ImgInfo));  /* 写入镜像信息 */
        uart_puts(" - OK \n");
        MMC_disk_finalize();
        set_param_linux(BOOT_MODE_MAX);             /* 设启动参数 */
        while (1);
    }

    /* ⑥ 备用路径：读 ROM.txt，按文件清单逐个写（IPL / PNLBL / uImage） */
    ret = Get_RomfileInfo(&file_info);
    ...
}
```

要点：

| 项 | 值 / 含义 |
|---|---|
| SLP 落点 | **DDR `0xc0007fc0`**（末尾对齐，注意是 `…fc0` 不是 `…000`） |
| 缓冲上限 | `0xa00000` = 10 MiB |
| 引导块 | `nand_EraseBlocks(0, 1)` —— **只擦第 0 块**，不是刷全片 |
| 之后 | 重启，由 SLP 内的升级流程完成真正写入 |

⇒ **dnloader 的职责极小**：读文件、搬内存、擦一格、写参数。这也解释了官方恢复
"闪烁 2–3 分钟"为什么主要时间花在后面的升级阶段。

## 3. 三种 loader 的分工（`print_bootloader` 的条件编译）

```c
#if defined(CONFIG_IPL)         "DRIMe4 IPL"
#elif defined(CONFIG_PNLBL)     "DRIMe4 PNLBL"
#elif defined(CONFIG_DNLOADER)  "DRIMe4 FLASH DOWNLOADER"
#endif
```

- **IPL**：最初级，链接 `D4_IPL.ld`
- **PNLBL**：panel bootloader，`D4_PNLBL.ld`
- **DNLOADER**：`dnloader.ld` → `0x70200000`

三者共用 `usr/Main.c` 一份主逻辑，靠宏切换入口分支（`Main.c:44 / 613 / 1423 / 1847`）。

## 4. NX500 不能直接用的五个差异

| 维度 | NX300 | NX500（实测） | 影响 |
|---|---|---|---|
| SoC | DRIMeIV | **DRIMe5s** | 所有寄存器基址不同，`bsp/` 整层要换 |
| 存储 | **NAND**（`drv/nand/`，坏块表、`nand_EraseBlocks`） | **eMMC**（`boot0.bin` 里 `dwcmob_*` + Toshiba/Samsung/Hynix 探测） | 存储驱动整层要换 |
| 板级自检 | GPIO `0x300503fc` bit4 | **未知** | 找不到就得去掉或换判据 |
| DDR | `init_lpddr2_400M/480M/500M/533M.h`、`init_ddr3_*` | 512 MB，参数**未逆** | 参数错 = 起不来，且无输出 |
| 固件名 | `nx300.bin` | `nx500.bin` | 一行宏 |

★ 但有一个有利的结构：NX500 的 `boot0.bin` 里**已经有** eMMC 读写、分区解析、镜像加载、
UART 打印（`fail : read emmc!` / `fail : write emmc!` / `DRIMe5 bootloader`），
**缺的只有 SD + FatFs 那一块**。

## 5. 三条路径（按风险排序）

### A. 从 `boot0.bin` 派生（推荐）

boot0 是 NX500 自己的第一阶段，**寄存器地址、DDR 初始化、eMMC 驱动全是正确的**。
只需补 SD 卡读取（NX300 的 `sd_api.c`/`sd_cmd.c` 是标准 SDHCI 协议，改基址即可）
+ FatFs（纯软件，可直接编译）。

风险：要写 boot0（4 MiB eMMC boot 分区）。写坏 = 只能靠 dnloader 救 = 死循环。
⇒ **必须在有 UART 的前提下做，且先在 SRAM 里跑通再落盘。**

### B. 从 NX300 源码移植（干净但工作量大）

把 `bsp/` 整层按 NX500 重写：UART 基址、eMMC 控制器、PMIC、DDR 参数。
工作量主要在"逆向 NX500 的寄存器表"，可从 boot0 里挖。

### C. 只做 UART 最小验证（第一步）

一个能在 `0x70200000` 跑起来、通过 UART 打印 `hello` 的裸二进制。
它验证三件事：**加载地址对不对、bootROM 认不认这个格式、UART 能不能通**。
这一步行了，A/B 才有意义；不行的，A/B 都是闭眼写。

## 6. 阻塞点：UART

`boot0.bin` 里有完整的 bootloader shell：

```
DRIMe5 bootloader / CA9 clock : 600Mhz / bootloader>
  test ddr [Test Count]
  test flash read  [Block No.]
  test flash erase [Start] [End]
  boot [mode]   0:cold 1:snapshot 2:warm
```

且 cmdline 模板含 **`console=ttyAMA0,115200n8`** ⇒ UART 物理存在，115200 8N1。

进入方式（公开资料，2016 年社区实践）：**micro-USB 上做电阻识别**，
三星常用阻值 `121K / 150K / 255K / 301K / 523K / 619K` 接地，配合 **3.3V** USB-UART 模块。

**没有 UART，dnloader 无法调试**——因为它的全部输出只有串口，屏幕不亮。

## 8. 未闭合

| # | 项 | 为什么没闭合 |
|---|---|---|
| 1 | NX500 的 dnloader 加载地址是否也是 `0x70200000` | 无样本，只能试 |
| 2 | bootROM 如何在 SD 上找 `dnloader.bin`（FAT 文件还是固定扇区） | 无文档；NX300 的 dnloader 自己用 FatFs，说明加载它的是**上一级**（SBL/PNLBL） |
| 3 | NX500 的板级自检判据（NX300 是 GPIO `0x300503fc` bit4） | 未逆 |
| 4 | NX500 的 DDR 参数 | 未从 `boot0.bin` 逆出（有 `DRAM_A clock` 等锚点） |
| 5 | NX500 的 SRAM/DDR 在 0x7xxxxxxx 段的映射 | 未验证 |
| 6 | 能否进 UART | 需硬件（电阻 + USB-UART），未做 |

★ 第 2 条最值得先查清：如果加载 dnloader 的是 **SBL 而不是 bootROM**，那意味着
"boot0 完好时根本不需要 dnloader"——恢复只需让 SBL 走它已有的升级分支。
这会大幅改变整个救砖策略的性价比判断。
