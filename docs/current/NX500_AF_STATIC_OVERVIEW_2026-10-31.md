## 0. 四条结论

| # | 结论 | 改动含义 |
|---|---|---|
| 1 | **主体保持已经有实现**：固件内含完整 face-box hold（冻结整份 `0x444` 人脸载荷，AF 区域自动切到冻结副本），由 `C3AStateLock*` 状态机在 **11 个点**启停 | 不用造，只需调策略（何时保持、保持多久） |
| 2 | **眼部 AF 是纯缺口**：双眼结果有、实时调用链有，但 AF 侧一处都不读 | 必须新增两段代码（谁跑眼部、谁用眼框） |
| 3 | **两套互不相干的命名空间**：`0xNNNNN` 形式属 `CAFData`，槽位形式属 `CIQ_SysDataIF_NX1` | 用错表会得到"看起来合理、实际错位"的名字 |
| 4 | **逐偏移扫描对 `SetParameter` 无效**：184 个槽只有一条通用写入口，存储地址由 id 算出来 | 找写入者要用"谁调虚函数"，不是"谁写 `+0x1c0`" |

## 1. 两套命名空间（最容易踩的坑）

|  | `CAFData` | `CIQ_SysDataIF_NX1` |
|---|---|---|
| ID 形式 | `0xNNNNN`（如 `0x1001e` / `0x30006` / `0x60084`） | 槽下标 0–183 |
| 编址 | `id = 块号 << 16 \| 下标` | `vptr + u32 slot[184] + 元数据块` |
| hub / 类 | 静态 hub `0x816d2ce0` | vtable `0x805de008`，typeinfo `0x805de2c4` |
| 规模 | 6 块 + 1 短数组，共 **330** 个 `u32` | **184** 槽（166 个有实现） |
| 名表 | 六块具名 | `0x5758e0` 的 184 条 `eIQ_ID_*` |
| 读写入口 | `hub_get 0x332948` / `hub_set 0x33273c` | 虚函数 `SetParameter(id, value)` |

`CAFData` 六块：`LensSpec`(39)、`Ae`(18)、`UserData`(11)、`State`(37)、`Debug`(61)、`Sequence`(164)。

> 第八轮的关键负结果：这两套**名字不能互借**。第七轮那张 184 条表读 `0x60084` 会给出整套错位但自洽的命名。

**类身份来自 RTTI，不是猜的**（Itanium ABI：`vptr[-4]` = typeinfo，`+4` 是长度前缀名字串）：

| vtable | typeinfo | 类名 | 槽数 | 代码范围 |
|---|---|---|---|---|
| `0x805de008` | `0x805de2c4` | `CIQ_SysDataIF_NX1` | 166 | `0x2bff08–0x2c17fc` |
| `0x805dea00` | `0x805dea48` | `CIQ_ParamInfo_NX1` | 13 | `0x2c4xxx` / `0x3b1xxx` |

## 2. 九轮各解决了什么

| 轮次 | 结论 | 关键地址 |
|---|---|---|
| 1 · 基线 | 原厂能力分层（205 点相位 / 209 点反差）、样本口径与 SHA-256；历史 Ghidra 反编译只作导航，关键分支以本 chunk 机器码复核 | — |
| 2 · 选人 | **主脸选择**：中心距离、脸面积的名次按 **6:3** 合并打分；打分本身**没有身份保持项**，前级已有几何匹配与平滑 | `0x143740` |
| 2 · 双眼 | 实时双眼定位算法**存在**且有实时取景调用路径（`CFDTask::EventHandler` → Smile/Wink → 双眼定位），但**尚无眼框 → AF ROI 闭环** | — |
| 3 · 相位 | 「相位序列可用镜头」标志实际读的是 **LensActuatorType**，链路：`0x2ff954` → 写数据项 `0x10004` → `CAFSequenceNxRoughFineScan::Initialize` 读并转 1 → 对象 `+0x10c` → 相位初始决策 | `0x34a13c`、`0x3b5de0` |
| 4 · `0x60084` | 完整六输入形式（概念重写，非原厂源码）：控制对象许可 `byte[0x110]`、镜头挂载 `0xecc`、镜头分级、`0x1001e`、`0x30006 == 6`、`GAF->dword[0xc98]` | `0x2f0ce4` |
| 5 · 覆盖 | 代码段实际只占镜像 **46%**（`0x570000` 以下），历史"某 ID 无写入者"的负结果原本只有 46% 覆盖面；按 12 MB 重扫后结论不变。新增 `symbols.py`：107,609 条可打印串可检索 | `0x570000` |
| 6 · 统一入口 | 所有数据项读取走**同一个函数** `0x332948(hub, id)`；块号 `(id>>16)&0xFF`，减 1 后查 **6 项跳表**映射到 hub 指针字段 | `0x332948`、跳表 `0x33297c` |
| 7 · **方法纠错** | 前六轮找不到 `IQ+0x1c0` / `IQ+0x2e4` 的写入者，**不是搜得不够深，是方法对这个对象不成立**：184 字段只有虚函数 `SetParameter` 一条通用写入口。同时用 RTTI 读出真名 | — |
| 8 · 第二空间 | 第六轮悬着的"6 个块是什么"有答案：`CAFData` 330 条；并用负结果钉死"两套命名空间不可混" | `0x816d2ce0` |
| 9 · 闭环边界 | 主体保持已有（`0x444` 载荷两个持有者）；眼部 AF 是接线缺口 | `0x81459b94`、`0x141a80` |

## 3. 人脸载荷与两个持有者

`0x444` 字节，最多 10 条，记录步长 `0x14`。

| 持有者 | 地址 | 谁写、谁读 |
|---|---|---|
| CFDTask 内载荷 | `this+0x54`（第二份 `this+0x4d4`） | 检测任务写、眼部算法读；`0x142f08/0x142f0c` 调 `0x50a114(this+0x54, 0, 0x444)` 清空 |
| 静态 face-info 单例 | `0x81459b94`，载荷 `+0x468` | `0x140b88` 返回；`0x141a80` 两条路径分别读它与 CFDTask 载荷 |

AF 侧只通过两个虚函数取数据（`CIQ_SysDataIF_NX1` vtable `0x805de008`），不直接读载荷。

## 4. 判据与工具

- **样本必须按 SHA-256 认**：`f8e417cb…dbff7f`。工作区里的 `p7_patched*` 不能当基准。
- **负结果要报覆盖面**：说"某 ID 没有写入者"之前，先确认扫描覆盖了整段代码区（46% → 12 MB）。
- **找写入者先问调用方式**：虚函数 + 由 id 计算地址的容器，逐偏移 `str` 扫描必然零命中，这不是"没有写入者"。
- 工具：`test_server/af_static/trace_roundN.py`（第 9 轮 120 条指令断言全通过）、`symbols.py`、`out/roundN/*.json`。

---

## 5. 边界（不要外推）

1. 本文所有地址是 **chunk 文件偏移**，写入运行时需按加载基址换算（见 `P7_DISPATCH_AND_LSC`）。
2. "眼部 AF 是缺口"是**静态**判断：有数据、有调用路径、AF 侧无消费者。运行时是否另有一条隐藏路径未排除。
3. "主体保持已有"指机制在，**没有实测**其触发条件与保持时长是否符合拍摄需求。
4. 第 5 轮的 46% 结论只针对**代码段位置**，不代表数据区被忽略。
