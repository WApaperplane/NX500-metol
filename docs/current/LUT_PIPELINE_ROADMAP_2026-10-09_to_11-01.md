### 5. ★ 关键待实证点：Still 拍片与"表被抢回"

> ★ **2026-10-09 更新：本节问题已有系统处理方案** —— 见
> [`P7_RECLAIM_COUNTERMEASURE_2026-10-09.md`](P7_RECLAIM_COUNTERMEASURE_2026-10-09.md)：
> **双通道隔离（表进 LUT1，p7 不碰）+ 寄存器级守护恢复（lutsentinel）**；
> 本节升级为"实验 E1–E5"（并入 U6 附录 A）。

#### 5.1 风险（诚实陈述）

历史实测：**半按快门**会让 p7 的 `View::_load` 重设表指针（"抢回出厂表"）。
推论：**快门（Still 流程）大概率也会触发一次从档位池的 load** ⇒ 直灌硬件 LUT0 的表
可能在拍照瞬间被覆盖为"档位表"——成片不带我们的 LUT。

#### 5.2 U6 §[6] 判据（已排入上机包，直接回答）

> 保持 Portra 表生效 → **不半按**、直接拍 1-2 张 → 与取景器比对。
> - **成片有色（跟随）** ⇒ 直灌即所见即所得 ⇒ 本链路"照片"一栏 ✅ 直接闭环。
> - **成片无色（被抢回）** ⇒ 转 §5.3 保底/或等 §5.4。

#### 5.3 保底路线（今天即可用，零门控）

**ksfilm 后处理**：拍原始 → 相机/PC 侧对成片做 LUT 处理（引擎已跑通 4 配方，跨环境
逐字节一致）。缺点：非实时、取景器不显示 LUT——按"拍原始 + 后处理"工作流使用。
（若选此路，建议取景器用 PW 通道做"预告"、成片用 ksfilm 定稿——两条通道配合。）

#### 5.4 进阶路线（G4 后）

把自定表**写进 p7 的档位池**（替换"自定义"档内容）→ p7 自己 load → 真·全程所见即所得
（含半按/拍片）。属改 p7 领域，**须 G4 转绿**（U4→U5 之后），不在本链路当前范围内。

### 3. 主动reload的证据应怎样表述

分享最后一次用户反馈是：自动reload后严重偏色花屏，半按可恢复；WorkBuddy随后移除了脚本中的reload。**撤回这一实现有依据；精确根因仍未确定。**

- `nx_regtabwrite.c::do_reload`直接写MMIO，最后只比较Load地址及Cfg是否与写入值相符。`RELOAD ok`不验证DMA完成、表内容已被正确消费或图像正常。
- A18写后diff=0，只证明采样时RAM与目标相同，不能排除写入过程中P7读取了部分表，也不能排除缓存、并发寄存器访问或缺少流程同步。
- 旧文档中针对CMA/SMA落点的“口袋体系外地址”解释不能直接套到A18。A18已经通过P7正常流程成功出片；两次实验的区别需要单独分析。
- `op_init`是Linux库配置接口，不能仅因“官方”就当作P7事件入口。重发PW同值是否会触发所需重载、是否保持全部用户参数，仍需先查发送端、接收端和变化通知条件。

当前可保留的工作路径是：写槽/登记表后等待已证实的半按事件。尚未证明点按即可稳定生效。

### 4. 本轮发现的具体实现问题

#### dry-run退出仍可能写相机

`nxui.c`选择滤镜时确实把`!live`映射到`status`，但末尾恢复逻辑只判断`if (lut_mode)`，没有检查`live`或本进程是否修改过LUT。于是`--lut --dry-run`或截图退出仍可能执行`lut.sh off`；若存在备份，就会写回登记表和A18。这与“dry-run只读”的说明不一致。

修复应围绕本会话是否实际取得并修改LUT状态，而不是只判断页面类型；离线回归需直接断言dry-run退出不会调用恢复写入器。

#### A18不是空闲槽，隔离结论有范围

原厂`Still6[0]`本来就是A18。把它当工作槽会影响仍选择这个槽的原厂路径。当前“Still负片、View正常”的单向对照成立，但不能推出所有条件下View/Still互不干扰；只改View时，未改的Still6仍可能选到已改内容的A18。

当前脚本只改`View4[3]`和Still6六项；其余View静态项、动态分支/BV登记表不在同一修改范围内，不能承诺所有模式均所见即所得。

#### 备份尚不是每个UI会话的独立事务

`lut.sh begin/apply`见到`state/a18_orig.bin`已存在就复用；`off`不删除该备份，Still备份也用固定日期路径。恢复View还硬编码为A17。因此现有代码实现的是“复用既有备份”，不能保证恢复到每次进入UI之前的状态。

`nxui.c`等待恢复子进程，但丢弃其退出状态并返回0。`off`又只验证RAM恢复，没有确认硬件已正常重载；关闭界面不等于画面立即恢复。应区分备份就绪、源数据已提交、待半按、生效待确认、源数据已恢复、硬件恢复待确认。

### 5. 接下来的优先级

1. 先收口dry-run、会话备份和恢复结果；不再以“命令返回成功”显示“画面已生效/完全恢复”。
2. 保留半按正常重载作为基线。沿P7现有消息/属性事件链寻找最小触发，先离线核对；不要直接换另一套裸寄存器序列试错。
3. 为连续切换补所有权/时序设计。正在被登记表引用的A18被逐字节改写，写后验证无法覆盖中间状态；不要假定这条路径已经无竞态。
4. 再做真实cube、重复切换、半按、拍JPEG、主动退出、失败恢复和模式切换的有界验收。当前三份转换样本包含恒等、反相和通道增益，尚不是任意色彩映射及解析边界的全面验证。

本轮只记录发现，没有修改上述运行工具或相机部署版本；也未提交或推送Git。

### 1. 现在的三条转换路径

| # | 在哪跑 | 工具 | 输入 | 什么时候用 |
|---|---|---|---|---|
| 1 | PC（浮点） | `native_codec.compile_uniform_rgb` / `film_physics.build` | 33³ RGB 设计立方体 | 自研胶片表：33³ 设计 → 一次浮点量化到 17³ native |
| 2 | PC（导入） | `tools/lutgen/web_import.py` | G'MIC 公开胶片 CLUT（13³/33³ Hald） | 外部 LUT 入库，含蓝通道最快的解码坑 |
| 3 | **相机（定点 Q16）** | `cube2lut.arm`（10,828 B，md5 `b798964d…`） | 任意规范 `.cube` | **机内转换**，33³ 用时 0.478 s |

三者的关系：1 和 2 产出的最终都是 19,712 B 槽表；3 是同一件事的 ARM 定点实现，**不需要 PC**。

#### 1.1 cube2lut 的格式契约（不是"什么都能吃"）

| 项 | 规定 |
|---|---|
| 输入 | `LUT_3D_SIZE N`，`N ≥ 2`，节点数必须恰为 N³ |
| 轴序 | **R 变化最快**（Adobe 规范）。非规范文件**不纠正**，直接产出错表 |
| DOMAIN | 只接受 `0..1`，否则报错退出（不猜） |
| 1D cube | 明确报错 |
| 输出 | 4,913 × `{Cr,Cb,Y,0}` + 60 B 填充 = 19,712 B |

> 科学计数法（`2.24e-05`）已于 10-18 修复。**旧发布包里的 8,880 B 版本是 RGB 直通，语义完全错**——若哪天从 GitHub release ≤10 重装，会把它装回来。部署前必核 md5 `b798964d`。

### 2. 机内链路现状（已经跑通，不是待设计）

```
/mnt/mmc/looks/<name>.cube  ──┐
/mnt/mmc/looks/<name>.bin   ──┤
                              ▼
                       lut.sh apply <name>
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   cube2lut.arm          nx_slotwrite.arm      nx_regtabwrite.arm
   （如是 .cube）        （写 A18 槽）        （View4 四项 +
   0.5 s / 33³           读回校验              Still6 + BV12）
                              │
                              ▼
              nx_lutload.arm once A18 → 等 DMA_RD_FINISH
                              ▼
                   秒切生效（不再需要半按快门）
```

| 命令 | 作用 |
|---|---|
| `lut.sh list` | 列 `/mnt/mmc/looks` 里的 look（同名 .cube 优先） |
| `lut.sh begin` | 备份 A18 + 记录还原点（只读，不写寄存器） |
| `lut.sh apply <名>` | 转（如需）→ 写槽 → 改三张登记表 → **秒切生效** |
| `lut.sh off` | 登记表回原厂 + A18 回备份 + 秒切 |
| `lut.sh status` | 当前 look / 备份状态 / 引擎指针 |

**NXUI 面板**：`nxui.sh lut` 用 `lut.sh list` 填列表、`lut.sh apply/off` 当执行器——所以面板上"实用功能 → LUT 滤镜"已经是这条机内链路。

### 3. 唯一缺口：文件怎么进 `/mnt/mmc/looks/`

现在只能拔卡或从 PC 走 FTP/ssh。三条补齐路径，按成本排：

#### 3.1 方案 A：手机 FTP 客户端（零开发，推荐先用）

事实：`onboard.sh` 开机无条件拉起 `tcpsvd -u root -vE 0.0.0.0 21 ftpd -w /opt/storage/sdcard`——
**FTP 21 默认开、可写、根目录就是 SD 卡**。

流程：
1. 相机连上 WiFi（或手机热点），记下屏幕 IP
2. 手机装任意 FTP 客户端（Solid Explorer / FE File Explorer / Documents）
3. 连 `ftp://<相机IP>`，root 空密码
4. 把 `.cube` 拖进 `looks/`
5. 相机面板 → LUT 滤镜 → 选它 → apply → 半按

**全程不碰电脑。**

#### 3.2 方案 B：网页上传（约 40 行，产品化）

相机已有 `busybox httpd` + `push-cgi`（8080，`/opt/usr/nx-ks/capdtm/www/cgi-bin/`）。
现有 `push` CGI 把目标路径硬限制在 `nx-rc/web_root/`，**不能写 SD 卡**。

新增一个 `lutpush` CGI 即可：

```sh
# 允许 path=looks/<name>.cube -> /mnt/mmc/looks/<name>.cube
# 校验：只允许 [A-Za-z0-9._-]+\.cube，禁 "/"、".."；单文件 ≤ 2 MB
# 写盘：.part → mv → sync（与 push-cgi 同款原子替换）
# 可选：写完后自动调 cube2lut 预热转换
```

再配一个极简页面（`<input type=file>` + 一个按钮），手机浏览器打开相机 IP 就能传。

优势：不装 App、不输密码、可顺便显示"当前 look / 库列表"。

#### 3.3 方案 C：相机直接拉（需确认相机能否出网）

NX500 的 WiFi 是 STA 模式（连路由器）。若路由器有外网：

```sh
wget -O /mnt/mmc/looks/xxx.cube http://<某处>/xxx.cube
```

再往上可以做"LUT 库订阅"：机上一个 URL 清单，开机比对 mtime 自动同步。
**前提未验证**：相机侧的 DNS/路由/证书。总线上一堆 TLS 依赖，`wget http` 比 `https` 稳。

### 5. 风险与坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **发布包里的旧二进制** | release ≤10 的 `cube2lut.arm` 是 8,880 B RGB 直通版。重装/升级会把它带回来，部署前必核 `b798964d` |
| 2 | ~~**不能从 ARM 侧强制 reload**~~ **已于 2026-11-08 推翻** | 旧结论「裸写 `+0x00c` + 脉冲会花屏」只对**不完整**的写序成立：漏了 `OnOff`/`Acc`/`Cfg` 通道位，且没复位 `+0x008` bit0。`nx_lutload.arm once` 复刻 p7 的 `FUN_004a5c44` 写序并等 `ACC_3DLUT_RD_FINISH`，现在 apply/off **自己完成 Load**，不再需要半按。见 [秒切记录](LUT_SWAP_MECHANISM_2026-10-16_to_11-08.md) |
| 3 | **`lut.sh apply` 会关"屏幕色彩"** | 首次记原值，`off` 还原。若进程被 kill，可能停在关闭态 |
| 4 | **SD 卡 exfat 重复目录项** | 反复覆盖同名 `.cube`（手机 FTP 尤其容易）会积累重复项。上传用新文件名，定期 `tar` 备份→改名重建 |
| 5 | **同名 .cube/.bin** | `apply` 优先 `.cube`。改了 `.bin` 但目录里还有旧 `.cube`，会被旧 cube 覆盖 |
