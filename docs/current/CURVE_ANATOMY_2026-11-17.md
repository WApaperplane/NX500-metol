### 0. 结论摘要（先看这里）

| 问题 | 结论 |

### 3. 调用点全枚举（方法 + 覆盖范围）

#### 3.1 扫描定义

对 `.text` 全段 3,019,712 个 4 字节对齐字逐一判定：

```
B   / BL  : cond != 0xF 且 bits[27:25] == 0b101
            target = addr + 8 + SignExtend(imm24) << 2
BLX(imm)  : cond == 0xF（单独统计；其目标必进 Thumb，落到 0x8017CF88 这种 ARM 偶数地址在语义上不成立）
```

另外补充三道交叉检查，防止漏网：

1. **条件分支**：判定不区分 cond，`BLEQ / BLNE / BLGT / BLCC ...` 全部计入（历史上漏过的是这一类）。
2. **尾跳**：`b` 型无条件跳转同样计入（同族壳 `0x8017CF40/84/3C` 就是用 `b` 尾跳进函数体的）。
3. **间接引用**：全镜像原始 dword 搜索 `0x8017CF88`（小端 `88 CF 17 80`）→ **0 命中**，说明没有代码把该地址装进字面量池或跳转表，排除 `blx rN` 型调用。

#### 3.2 结果：仅 3 个调用点

| # | 调用点 | 指令 | 所属函数 | 调用前 3 条指令（上下文） |
|---|---|---|---|---|
| 1 | `0x801377B4` | `bl 0x8017CF88` | `0x80137514` | `mov r0,r4` / `ldr r1,[pc,#0x5fc]` / — |
| 2 | `0x8038F868` | `bl 0x8017CF88` | `0x8038DFE4` | `strh r3,[r8,#0xf4]` / — / — |
| 3 | `0x80390A18` | `bl 0x8017CF88` | `0x8038F90C` | `strh r3,[sl,#0xcc]` / — / — |

> 注：`0x801377B4` 那条不是"无条件 bl 漏条件码"的问题，而是**同一段线性下发序列里**紧跟着 `wb / lcac / r_b_scale / sig / sra / ...` 一长串同族 setter，tc 只是其中之一。

#### 3.3 壳的唯一性复核

对**函数体** `0x8049E4D4` 再做一次同样的全镜像扫描：只有 1 条指令指向它 —— `0x8017CFCC b 0x8049E4D4`（即壳自己的尾跳）。

于是完整度为：
```
3 个 bl → 0x8017CF88 → 1 个尾跳 → 0x8049E4D4
```
不存在"绕过壳直接进函数体"的旁路。**"这条写入路径在全镜像里的入口数 = 3"是可以封口的结论。**

#### 5.1 定名方法（可复现）

1. **函数自名**：镜像 `0x806E0000–0x80740000` 是一张"函数名 + 文件:行"的字符串池（`_ipc_get_subparam_*`、`d5_ipc_set_subparam_*` 等）。几乎每个函数在 **assert/error 分支**里用 `ldr rX,[pc,#imm]` 加载自己的名字。于是：
   - 建 `字面量池地址 → ldr 指令地址` 映射；
   - 建 `dword → 槽地址` 映射（槽值落在 `0x80560000–0x80740000`）；
   - 两级反查即得 `函数地址 → 名字`。本次共解出 **4,381** 个函数名（`tools/names.json`）。
2. **C++ 类名**：vptr → `[vptr-4]` = typeinfo → `[typeinfo+4]` = Itanium 风格名字（`"11CIpcGammaD5"` 是 `<长度><名字>`）。
3. **行为旁证**：本报告所有关键节点都同时有"字符串"+"行为"两条独立证据（例如 `0x8038DFE4` 既有 `gamma.txt` / `GAMMA_INDEX` 字符串，也有 `sprintf → ParseParam → GetValue` 的调用序列）。

### 6. 路径分类结论

| 调用点 | 所属函数 | 分类 | 判据（靠什么判的） |
|---|---|---|---|
| `0x801377B4` | `0x80137514` `IpcParam::InitGroup` | **初始化 / 开机（每次 liveview 后端 Init 一次）** | ① 上游 `Ipc_Initialize()` 名字 + 文件名 `CBackend_Ipc_View_Sra.cpp`；② 上游两级 `ldrb flag; cmp #0; beq` 一次性守卫；③ 本函数 `switch(group){0,1,2}` 三组全量下发；④ 无循环包围调用点；⑤ 一次调用下发 wb/lcac/sig/sra/... 整个家族 —— 典型"上电铺参数"。 |
| `0x8038F868` | `0x8038DFE4` `CIpcGammaD5::LoadGammaFile` | **文件加载 / 调试-产线（on-demand）** | ① 字符串 `gamma.txt` + `GAMMA_INDEX`；② 调用序列 `sprintf("%s/%s") → ParseParam → GetValue(section)`；③ 解析函数返回 0 即提前 `return`（`0x8038E014 cmp r0,#0; 0x8038E018 bne` 才继续），说明是可选的外部配置；④ 无循环包围调用点。 |
| `0x80390A18` | `0x8038F90C` `CIpcGammaD5::ApplyGammaCurve` | **派生自上一行（曲线装配后下发）** | ① 唯一镜像内调用者是 `0x8038E084`（虚表 +0x18），属 `0x8038DFE4` 的函数体；② 函数把打包位域（`0x803C55B8` 取位域）展开成 108 字曲线；③ 无循环包围调用点。 |

**没有一条落在 still capture、liveview 每帧、video record 上。**

补充说明（容易误判的点）：

- `0x801D9D38` 位于 `CBackend_Ipc_View_Sra`（liveview 后端）里，但它是 `Ipc_Initialize`，**每次 liveview 会话建立时执行一次**，不是每帧。同理 `0x801CD098` 在 `CBackend_Ipc`（基类）虚表里，也是创建期回调。
- `0x8038F90C` 内部确有多个循环（39 条回边），但都是"把 11/33/108 点装配成 LUT"的**数据循环**，不是帧循环；其调用点 `0x80390A18` 在循环外。
- `0x8049E4D4` 自身有一个 108 次迭代的拷贝循环 —— 那是**单次写入的展开**，不是每帧重复。

### 7. "每帧"证据检查（Q3）

| 检查项 | 方法 | 结果 |
|---|---|---|
| 调用点是否被循环包围 | 对 3 个函数各做回边枚举（`b<cond>` 且 target < addr 且不是 bl），判断是否存在 `target ≤ call ≤ addr` | `0x80137514`：16 条回边，包围 0；`0x8038DFE4`：61 条回边，包围 0；`0x8038F90C`：39 条回边，包围 0 |

### 9. 对"实时预览热更新"的工程结论

1. **固件原生行为**：曲线只在两个时机被下发 —— ① liveview 后端 `Ipc_Initialize()` 一次；② 有人调用 `gamma.txt` 加载。**取景每帧、录像每帧都不会重推曲线。**
2. **函数本体的性质**（决定改造成本）：
   - `d5_ipc_set_subparam_tc(idx, buf108)` 是**纯拷贝**：无缓存、无状态机、无锁存、无返回值依赖（成功返回 0，`buf==NULL` 返回 -1 并打 assert）。
   - 因此它**可以安全地被每帧调用**（幂等），但也没必要 —— 每次调用都会完整重写 432 字节到 DDR 参数槽，属于纯带宽浪费。
3. **热更新可行的最小方案**：
   - 在任意"参数已变更"的位置（例如 UI 改曲线、或你自己的帧钩子）调用一次 `d5_ipc_set_subparam_tc(ch, curve108)`；
   - **注意 `ch`（`subIdx`）**：`CIpcGammaD5` 有两个实例，构造时 `strb 0` / `strb 1` 区分（`0x8038552C` / `0x80385530`），取通道号的是 `0x803C59F0`（读 `[this+0xC]` 的 `[+0xD]` 字节，归一化为 0/1）。**要热更新的通道必须与当前取景通道一致**，否则改的是另一条通路。
   - **提交**：本函数只写 DDR，不触发参数集生效。同家族存在 `d5_ipc_update_sram_ip`（`0x804971BC`）与 `d5_ipc_set_preset_subtop_ctrl`（`0x8017C…`）等提交/切换入口。真正的"下一帧生效"取决于 ISP 参数集是否被重新 latch —— 这一点静态分析无法确证，需要在 `d5_ipc_update_sram_ip` / `set_preset_subtop_ctrl` 的调用时机上继续验证，或用动态手段确认。
4. **一句话**：**"每帧刷新"的现成通路不存在；"改一次、下一帧生效"的通路在函数层面是通的，但需要一个新增调用点 + 一次参数集提交。**

> 来源：`CURVE_DDR_LAYOUT_2026-11-17.md`（已归档至 `docs/archive/`）

- 日期：2026-11-17
- 固件：`E:/NXWA/fw/v1.12/p7_wrapped.elf`（唯一 PT_LOAD：vaddr=0x80000000，off=0x1000，filesz=0xB84280）
- 地址换算：`file_off = addr - 0x80000000 + 0x1000`（vaddr 上限 0x80B84280；`0x813EBF50` 不在镜像内，属运行期 RAM）

### 0. 一句话结论

写表函数 `0x8049E4D4` 是**纯平铺 108 字拷贝**（`dst[i] = src[i]`，i=0..107），它不做任何通道/节点重排。
因此 108 字的结构完全由生产者 `0x8038F90C` 决定，实测（符号执行）结果是：

> **432 字节 = 2 个 216 字节子块；每个子块 = 108 个 u16 = `X[22] + Y[22] + A[21] + B[21] + 22×0`。**
> **不是 4 通道 × 27 点，也不是 4 通道 × 19 点 + 32 字。**

通道维度不在这 108 字里：每个通道是**独立对象实例**，各自调用一次计算 + 一次写表（`r0` = 实例号）。

### 1. 调用链（L1）

```
obj(通道实例) ──> 0x8038F90C(obj, arg)          ; 计算 + 打包 432B 到栈上 sp+0x1F8
                0x80390A18  bl 0x8017CF88(handle, buf)
                             └─ 0x8017CF88: 上报 + 尾分支
                                0x8017CFCC  b 0x8049E4D4(instance, buf)   ; 108 字平铺拷贝

关键点：`0x8049E4D4` 在全镜像里**没有任何 BL 调用点**（`findbl.py` 扫描结果为空），唯一静态入口是 `0x8017CFCC` 的尾分支；`0x8017CF88` 的调用者是 `0x801377B4`、`0x8038F868`、`0x80390A18`。

0x8017CFC0  mov  r1, r4            ; r4 = buf (sp+0x1F8)
0x8017CFC4  add  sp, sp, #0xc
0x8017CFC8  pop  {r4, r5, lr}
0x8017CFCC  b    #0x8049e4d4       ; <<< 尾分支进入写表
```

### 2. 写表函数 0x8049E4D4：确认是平铺拷贝（L1）

```
0x8049E4D4  cmp  r1, #0
0x8049E4D8  push {r3, r4, r5, lr}
0x8049E4DC  ldrne r5, [pc, #0x48]     ; = 0x813EBF50（实例基址指针数组，运行期 RAM）
0x8049E4E0  movne r3, #0
0x8049E4E4  beq  #0x8049e514
0x8049E4E8  asr  r4, r3, #2           ; r4 = 字节偏移 / 4 = 字索引 i
0x8049E4EC  add  r2, r3, #0x1f00
0x8049E4F0  ldr  ip, [r5, r0, lsl #2] ; ip = base[instance]
0x8049E4F4  ldr  r4, [r1, r4, lsl #2] ; r4 = src[i]  ← 源缓冲按字线性取
0x8049E4F8  add  r3, r3, #4
0x8049E4FC  add  r2, r2, #0x28        ; r2 = 0x1F28 + 字节偏移
0x8049E500  cmp  r3, #0x1b0           ; 0x1B0 = 432
0x8049E504  str  r4, [r2, ip]         ; dst = base[instance] + 0x1F28 + 4*i

```

结论：
- 目的地址 = `base[instance] + 0x1F28 + 4*i`，i = 0..107；`base[]` 取自 `0x813EBF50`（运行期，静态读不到 → 表地址本身是 **L3**）。

- 旁证：`0x1F28 + 0x1B0 = 0x20D8`，正好是兄弟函数 `0x8049E538` 写的控制块起点 `base+0x20C0+0x18`，两块首尾相接不重叠（L1）。

### 4. 108 字 / 216 个 u16 的完整映射（L1，符号执行逐条核对）

打包代码把 216 个 16 位值写进 `sp+0x1F8 .. sp+0x3A7`，**216 个偏移全部覆盖、无重复写**（只有每块最后一个 u16 找不到写点，见 §8）。写点覆盖关系由 `emu2.py` 从 `0x8038FCA8` 到 `0x80390A18` 逐条模拟得到。

#### 4.1 公式（可直接实现）

设缓冲区字节偏移 `off = 0..431`：

```
blk  = off // 216           # 0 = 前半块(字节 0..215)，1 = 后半块(字节 216..431)
b    = off % 216            # 块内字节偏移
u    = b // 2               # 块内 u16 序号 0..107
hi16 = (off % 4) == 2       # 同一个 32 位字里，偶地址=低半字，奇地址=高半字

u <= 21        -> X[u]           # 22 个：x 坐标
22 <= u <= 43  -> Y[u-22]        # 22 个：y 值
44 <= u <= 64  -> A[u-44]        # 21 个：段系数 A
65 <= u <= 85  -> B[u-65]        # 21 个：段系数 B
86 <= u <= 107 -> 0              # 22 个 u16 恒 0
```

#### 4.2 32 位字级映射（块内字索引 w = 0..53，块 1 再加 54）

| 字 w | 低半字 | 高半字 | 说明 |
|---|---|---|---|
|0|X[0]|X[1]|X[0..2] = 暗电平常数 -1024/-439/-146 |
|1|X[2]|X[3]|X[3] = C0 曲线第 1 点 |
|2..10|X[2w]|X[2w+1]|X[4..21]，X[21] 被强制为 0x3FFF |
|11|Y[0]|Y[1]|Y[0..2] = 由第一段反向外插 |
|12..21|Y[2w-22]|Y[2w-21]|Y[3..21] = 19 点曲线（块 0 已过二次曲线，块 1 未过）|
|22..31|A[2w-44]|A[2w-43]|A[0..19]|
|32|A[20]|B[0]|跨数组边界 |
|33..42|B[2w-65]|B[2w-64]|B[1..20]|
|43..53|0|0|22 个 u16 全 0 |

对应 DDR 绝对地址：`base[instance] + 0x1F28 + 4*w`（块 0）、`+ 4*(w+54)`（块 1）。**整块 108 字 = 2 个子块 × 54 字**。

#### 4.3 位宽（L1）

```
0x8038FCB8  bfi  sl, sb, #0, #0xf     ; X 写低 15 位（bit15 保留原值，本次执行恒 0）
0x8038FE54  bfi  sl, sb, #0, #0xb     ; Y 写低 11 位（bit15..11 保留原值）
0x8038FF94  ldr  r3, [sp, #0x4c] ...  ; A/B 直接 strh 低 16 位，无掩码
0x803901CC  bfc  r4, #0, #0x10        ; 填充区清零
```

X 用 15 位是有意义的：`-1024` 按 15 位补码 = `0x7C00`，与 `0x3FFF`(16383) 正好同一字段（L1 算术，L2 语义）。
Y 只留 11 位 → 负数会被截断成 `v & 0x7FF`；只有当 `Y[0..2]` 非负时才安全（见 §9 未解项）。

### 5. 19 → 108 的重采样：没有 27 点插值（L1）

1. **不存在 27 点**。整个函数里没有任何 `#0x1b` / 27 次循环；`#0x1b` 只出现在别处无关代码。19 → 硬件表的真实路径是 **19 → 22 节点 → 21 段**：
   - `sp+0x148` 起 44 个字 = 22 个 X，`sp+0x1A0` 起 44 个字 = 22 个 Y（`0x1A0-0x148 = 0x58 = 22*4`）。
   - 19 点位于 **索引 3..21**（`sp+0x154` 与 `sp+0x1AC` 就是 22 点数组的第 3 项）；前面 3 点是被拼上去的"黑外区"节点。
   - `0x8038DCE0` 的第 7 参 = `0x16`(22)：`0x8038FC84  mov r3, #0x16; str r3, [sp, #8]`，它对 22 个节点算 21 段系数（A/B/C，`0xF4-0x4C = 0x54 = 21*4`）。
2. **x 网格不是均匀网格重建，而是沿用非均匀 X19**：`0x8038FB0C` 的循环只做"尾部修正"——从尾部往前找最后一个 `X <= 0x3FFE` 的点，再从该点起按 `步长 = (0x3FC0 - X_prev + 0x3F) / 剩余段数` 补齐到 `0x3FFF`：
   ```
   0x8038FAE4  movw r1, #0x3ffe          ; 截止阈值
   0x8038FB14  ldr  fp, [r3]             ; X[k]
   0x8038FB1C  cmp  fp, r1
   0x8038FB28  ble  #0x80390b68          ; 找到 → 转去正常路径
   0x80390B68  ldr  r8, [sp, #0x34]      ; X 数组基址
   0x80390B80  rsb  sl, r7, #0x12        ; 剩余段数 = 18 - k
   0x80390B94  str  sl, [sp, #0x20]
   0x80390B98  b    #0x8038fb5c
   ...
   0x8038FBA0  rsb  r8, fp, #0x3fc0      ; 0x3FC0 - X_prev
   0x8038FBA8  add  r8, r8, #0x3f        ; +0x3F
   0x8038FBAC  udiv r8, r8, r2           ; / 剩余段数
   0x8038FBDC  add  fp, r7, fp           ; X = X_prev + step*...
   0x8038FBE4  ldr  r0, [sb, #-0x1fc]    ; 同一轮还会为新 X 重插值 Y
   0x8038FBE8  str  fp, [r8, #-0x254]    ; 写 sp+0x154+4k (X)
   0x8038FC24  str  r0, [r8, #-0x1fc]    ; 写 sp+0x1AC+4k (Y)
   ```
   对默认 X19（最大 16383 > 0x3FFE）→ 命中 k=20，只重写 `X[21] = 0x3FFF`，其余保持原非均匀值。
   **⇒ 非均匀网格（0/32/74/…/15872）原样进入硬件表；不是"固定均匀网格"。**
3. **段内插值由硬件用 A/B 做**（不是软件先插成 27 点）。A/B 各 21 个，一 一对应 21 段：
   ```
   0x8038DF7C  lsl  r8, r8, #0xd         ; 整数部分 <<13
   0x8038DF80  addlt r7, r7, #0x2000     ; 负小数补 2^13（借位）
   0x8038DF88  add  r7, r8, r7           ; B[i] = (int<<13) + frac  → Q13 定点
   0x8038DF74  str  r0, [r1, r4]         ; A[i] = 整数部分
   0x8038DF94  str  r3, [r0, r4]         ; C[i] ≡ 0（str r3,#0）
   ```
   `B` 明确是 **Q13 定点**（L1）。A 是整数部分（L2）。二者合成 y 的公式未在镜像里直接出现 → 归入未解项。

### 6. X 坐标的去向（回答 Q3）

- **写进去了**：每个 216 字节子块的头 22 个 u16（字节 `+0x000..+0x02B`），值 = `X[0..21]`，15 位宽。
  - `X[0..2]` = 常数 `-1024 / -439 / -146`（来自 `0x8062F898`，在 `0x8038FAE8` 存入 `sp+0x148..0x150`，前缀为暗电平/黑外区节点）。
  - `X[3..21]` = C0 曲线的 19 个 x；尾部修正保证 `X[21] = 0x3FFF`。
- **不是"只用于计算时定位"**：X 与 Y/A/B 一起进 DDR 表（L1）。
- 反汇编依据：
  ```
  0x8038FCA8  add  r1, sp, #0x200
  0x8038FCA8  ldrh sl, [r1, #0xd0]      ; 读 OUT[0xD8]
  0x8038FCB0  ldr  sb, [sp, #0x148]     ; X[0]
  0x8038FCB8  bfi  sl, sb, #0, #0xf
  0x8038FD44  strh sl, [sb, #0xd0]      ; 写 OUT[0xD8]
  ```

### 7. 0x803C55B8 是什么（回答 Q4）

**不是"从对象取某通道的 19 点"**，而是一个 **32 位打包位域取数器**（`get_bitfield(obj, word, idx)`）：

```
0x803C55B8  push {r3, r4, r5, lr}
0x803C55BC  ldr  r3, [r0, #0x1c]        ; 字段个数
0x803C55C0  cmp  r3, r2
0x803C55C4  ble  #0x803c5610            ; 越界 → 断言
0x803C55C8  ldr  r3, [r0, #0x18]        ; 字段宽度数组
0x803C55D0  ldr  r0, [r3, r2, lsl #2]   ; width = widths[idx]
0x803C55D4  mvn  r5, #0
0x803C55DC  mvn  r5, r5, lsl r0         ; mask = (1<<width)-1
0x803C55E0  ble  #0x803c5624            ; idx<=0 → shift 走特殊分支
0x803C55E4  add  r4, r3, r2
0x803C55E8  mov  r2, #0
0x803C55EC  ldr  ip, [r3], #4           ; 累加前 idx 个字段宽度
0x803C55F0  cmp  r3, r4
0x803C55F4  add  r2, r2, ip
0x803C55F8  bne  #0x803c55ec
0x803C55FC  rsb  r2, r2, #0x20
0x803C5600  rsb  r2, r0, r2             ; shift = 32 - sum(prev) - width
0x803C5604  and  r0, r1, r5, lsl r2
0x803C5608  lsr  r0, r0, r2             ; (word >> shift) & mask   ← MSB-first 打包
0x803C560C  pop  {r3, r4, r5, pc}
```

- 函数体 **0x54 字节 / 21 条指令**（0x803C55B8–0x803C560C）。
- 内部循环边界 = **调用参数 idx**（即通道号 0..3，最多 3 次累加），不是 19 也不是 27。
- 在 `0x8038F90C` 里被连调 4 次（`r2 = 0,1,2,3`）取出配置字的 4 个字段；`field0` 决定数据源分支（`cmp r7,#4`），`field1/field2` 作为 7 字/项系数表的索引（`rsb r6,r6,r6,lsl #3` = ×7，`0x8062F8C0 + 28*field`）。
- 该地址确实作为函数指针出现在 `0x8062F6C8`（同表还含 `0x8038F90C`、`0x8038DA20` 等，是类 vtable 段）。

### 8. 两块子表为什么看起来"一样"、结尾两个 u16 为什么没写

- 符号执行时我把步骤⑨的二次曲线循环跳过了（`0x80390218 → 0x80390240`），所以模拟结果里两块一致。**真实运行中两块不同**：
  - 块 1（字节 216..431）= 用目标曲线（`obj+0xEDC/0xF28`）算出的 Y；
  - 块 0（字节 0..215）= 同一批 Y 再经 `0x80390218–0x8039023C` 的固定 17 点曲线变换后的 Y，并重算 A/B。
  ```
  0x803901D0  add  r7, sp, #0x1ac        ; 起点 = Y[3]
  0x80390208  add  r5, sp, #0x1f8        ; 终点 = Y 末尾
  0x80390218  ldr  r0, [pc, #-0x658]     ; = 0x8062FC5C (17 点 x 表)
  0x8039021C  ldr  r3, [sl]              ; y = Y[i]
  0x80390220  add  r1, r0, #0x44         ; = 0x8062FCA0 (17 点 y 表)
  0x80390224  mov  r2, #0x11             ; n = 17
  0x80390228  bl   #0x803887f0           ; 单调三次插值求值器
  0x8039022C  cmp  r0, r4                ; r4 = 0x3FF
  0x80390230  strle r0, [sl], #4
  0x80390234  strgt r4, [sl], #4         ; 钳到 1023
  0x8039023C  bne  #0x80390218
  ```
  17 点固定曲线（`0x8062FC5C` / `0x8062FCA0`，L1）：
  x = {0, 0x220, 0x2A8, 0x2CA, 0x2EC, 0x30B, 0x32B, 0x34C, 0x368, 0x384, 0x39F, 0x3B8, 0x3D0, 0x3DA, 0x3E5, 0x3F1, 0x3FF}
  y = {0, 0x200, 0x280, 0x2A0, 0x2C0, 0x2E0, 0x300, 0x320, 0x340, 0x360, 0x380, 0x3A0, 0x3C0, 0x3D0, 0x3E0, 0x3F0, 0x3FF}
- 每块最后一个 u16（字节 `0xD6` 与 `0x1AE`）在 0x8038F90C 里**找不到任何写点**（169 个覆盖点 + 清零全覆盖，唯独这两处）；怀疑对齐填充/未使用，需实机确认（**L3**）。

### 10. 108 字结构：候选排序与证据强度

| 候选 | 判定 | 强度 |
|---|---|---|
|A. `2 × (X22 + Y22 + A21 + B21 + 22×0)`（均为 u16）|**成立**：216 个 u16 的写点全部定位，符号执行无遗漏、无冲突|**L1**（指令级）＋L2（A/B 语义）|
|B. 4 通道 × 27 点|**否**。写表函数是平铺 108 字；生产者里没有任何 27 次循环，也没有按 27 分组的步长|L1（排除）|
|C. 4 通道 × 19 点 + 32 字其它|**否**。19 点只占 `X[3..21]/Y[3..21]`，其余是黑外区节点与段系数|L1（排除）|
|D. 交错排列|**部分成立但表述不准**：不存在"通道×节点"交错；存在的是"同一 32 位字含两个 u16 字段"的打包（低半字/高半字，跨数组边界：字 32 = {A[20], B[0]}）|L1|

通道维度的正确理解（L2）：4 个通道是 4 个对象实例，各自算一次、各自写一次表（`base[instance] + 0x1F28`）。`0x8038F90C` 里出现的 4 次 `0x803C55B8` 只是取**同一对象的配置字里的 4 个字段**，不是 4 个通道的数据。

### 11. 未解项清单

1. **A/B 的合成公式**（L3）。已知 B = Q13 定点（`0x8038DF7C/0x8038DF80/0x8038DF88`）、A = 整数部分、C ≡ 0；是 `y = (A*x + B) >> 13` 还是 `y = A + (B*(x - X[i])) >> 13`，镜像里没有直接体现（HW 侧行为）。
2. **填充区 22 个 u16 的语义**（L2）。恒 0；数量正好 = X/Y 长度，也可能是"从未使用的第三系数数组 C(21) + 1 个对齐"，无法从静态代码区分。
3. **每块最后一个 u16（0xD6 / 0x1AE）无写点**（L3）。
4. **`base[instance]` 的真实值**（L3）。`0x813EBF50` 在运行期 RAM，静态为空；此前推测 bank1 = 0xBB71D300，未验证。
5. **两块子表的用途差异**（L3）。静态可证"块 0 = 块 1 的 Y 再过一次 17 点固定曲线、并重算 A/B"，但硬件把这两块当"两个通道 / 两个 bank / 两次采样"中的哪一种，需要写寄存器后回读 DDR。
6. **legacy 分支（`field0 <= 4`）**（L3）。此时数据源 = `0x8062F6F8 + 76*field0` / `0x8062F744 + 76*field0`，与默认 X/Y 表错位重叠，静态看不出其自洽性；推测是另一套 12 点/旧格式兼容路径，需实机。
7. **Y[0..2] 的 11 位截断**（L3）。外插可能为负（最低到 -1023），而 `bfi #0,#0xb` 只保留低 11 位 → 会出现 `v & 0x7FF`。是否真会出现负值，取决于 C0 首点 Y 与 X[3]。
8. **X/Y 条目的保留位**（L3）。X 用 `bfi #0,#15`、Y 用 `bfi #0,#11`，高位是"读-改-写"保留下来的栈内容；我按 0 处理。若实机读到非 0 高位，说明别处有预清零（未见）。

### 附：108 字掩码实证（2026-11-17 补，解掉块布局冲突）

同源外部仓库 `_ext_nx500srw/work/r10j-frame-flow/core/src/rtos_gamma.inc` 的
`gt_apply()` 给出了**实际使用的掩码规则**，这是第三方独立实现，与我们的静态推断互相印证：

```c
for (unsigned i = 0; i < 108; i++) {
    unsigned j = i % 54;                       /* ← 108 = 2 组 × 54 字 */
    uint32_t mask = j < 11  ? 0x7FFF7FFF       /* 15 位 ×2 */
                  : j < 22  ? 0x07FF07FF       /* 11 位 ×2 */
                  : j == 53 ? 0x0000FFFF       /* 仅低半字 */
                  :           0xFFFFFFFF;
    target[i] = (DDR[i] & mask) | (saved[i] & ~mask);
}
```

#### 结论：每 54 字 = 107 个 u16 字段 + 1 个填充

| 区段 | 字数 | 字段数 | 位宽 | 掩码 |
|---|---|---|---|---|
| X | 11 | 22 | 15 bit | `0x7FFF7FFF` |
| Y | 11 | 22 | 11 bit | `0x07FF07FF` |
| A / B / C | 31 | 21+21+21 = 63 | 16 bit | `0xFFFFFFFF` |
| 尾 | 1（`j==53`） | 1（仅低半字） | 16 bit | `0x0000FFFF` |

**⇒ 上一轮"X[22]+Y[22]+A[21]+B[21]+22×0"的结论作废**：末尾那 22 个"零"实际是
**A[21] / B[21] / C[21] 三个数组**，不是填充。`C` 恒 0 但**占位、必须写**。

X 用 15 位、Y 用 11 位的位宽也解释了为什么 C0 的 X 上限是 16383（14 位有效）而 Y 是 1023（10 位有效）——
编码各留 1 位余量。

#### 硬件接受的输入域（来自 `gt_request_valid`，硬约束）

```c
X[0] == 0            X[18] == 16383       /* 端点钉死 */
Y[0] <= 0            Y[18] == 1023        /* 黑白点钉死 */
X 严格递增            Y 单调不减           /* 不允许任何反向 */
其余 17 点：X∈[0,16383]、Y∈[-1024,1023]
```

`Y[-1024,1023]` 允许负值（下探到 -1024），比 C0 的 0–1023 宽 —— 负 Y 用于趾部压黑。

#### 对象构造（`gt_apply` 里的 vtable 与参数组）

```c
o[0] = 0x8062F6B0;  o[2]=metadata; o[3]=parent; o[6]=widths; o[7]=5;
*(uint32_t*)metadata = 2;  *(uint32_t*)(parent+12) = 256;
widths[5] = {3, 5, 4, 13, 2};    /* 合计 27 */
```

即计算函数 `0x8038F90C` 需要的是一个 **vtable 对象 + 5 组宽度 3/5/4/13/2 的参数**，
而不是裸数组。这是自建装载路径时最容易漏的一环。

#### 装载是「两段式」

1. `obj+0xEDC[19] = X`，`obj+0xF28[19] = Y`
2. 调 `0x8038F90C(obj, 0xAA000000, 0)`，然后**回读** `obj+0xE40[19]` 与 `obj+0xE8C[19]` 校验
3. 只有回读一致才拼 108 字并调 `0x8049E4D4`

`bank0`（`0xBB71D228`，与 bank1 差 0x2000）**全程只哈希不写**，用来证明没有误伤另一 bank。

### 1. 22 节点与 21 段是怎么造出来的（Q1）

#### 1.1 帧内数据布局（L1）

`0x8038F90C` 栈帧 0x3AC，与曲线相关的区域：

| 栈偏移 | 内容 | 说明 |
|---|---|---|
| `sp+0x4C` | `A[21]` (u32) | `0x8038DCE0` 第 1 输出 |
| `sp+0xA0` | `B[21]` (u32) | 第 2 输出 |
| `sp+0xF4` | `C[21]` (u32) | 第 3 输出，**恒 0** |
| `sp+0x148` | `X[22]` (u32) | 索引 0..2 = 黑区常量，3..21 = C0 的 19 个 X |
| `sp+0x1A0` | `Y[22]` (u32) | 索引 0..2 = 反向线性外插，3..21 = 目标曲线 19 个 Y |
| `sp+0x1F8` | 输出 432 B | 打包目标，`0x80390A18` 交给 `0x8017CF88` |

`(0x1A0-0x148)/4 = 22`、`(0x1F8-0x1A0)/4 = 22`、`(0x154-0x148)/4 = 3`、`(0x1AC-0x1A0)/4 = 3`
—— 19 点固定落在索引 **3..21**，前面 3 个槽是拼上去的黑区节点。这是"19→22"的全部含义。

#### 1.2 索引 0..2：反向线性外插（L1，`0x8038FA80–0x8038FB08`）

```
0x8038FA80  ldr r3,[sp,#0x1AC]      ; r3 = Y[3]
0x8038FA88  add r1,r3,#0x3FC; add r1,r1,#3    ; = Y[3]+0x3FF
0x8038FA9C  smull + 0x55555556>>32  ; /3 （乘倒数，magic 0x55555556）
0x8038FAA8  rsb r2,r3,r2             ; ΔY = Y[4]-Y[3]
0x8038FAAC  rsb r4,r4,ip             ; = X[3] - k3     (k3 = -146，来自 0x8062F898+8)
0x8038FAB0  mul r2,r4,r2
0x8038FAC0  rsb ip,ip,lr             ; ΔX = X[4]-X[3]
0x8038FAC4  sdiv r2,r2,ip            ; d0 = (X[3]-k3)*ΔY/ΔX
0x8038FAC8  cmp r2,r1 ; movge       ; d = min(d0, (Y[3]+1023)/3)   ← 钳位
0x8038FAD0  sub lr,r2,r2,lsl#2 ; add lr,r3,lr   ; Y[0] = Y[3] - 3d
0x8038FAD4  sub ip,r3,r2,lsl#1                  ; Y[1] = Y[3] - 2d
0x8038FADC  rsb r3,r2,r3                        ; Y[2] = Y[3] - 1d
```
X 侧不是算出来的，而是**三个常量**（`0x8038FAE0` 起从 `0x8062F898` 搬 3 个字）：

```
0x8062F898: 0xFFFFFC00 0xFFFFFE49 0xFFFFFF6E  →  -1024, -439, -146
```

即 `X[0..2] = {-1024, -439, -146}`（非线性、固定），`Y[0..2] = Y[3] - {3d,2d,d}`。
默认曲线（X[3]=0, ΔY=16, ΔX=32）→ `d=73` → `Y[0..2] = {-219,-146,-73}`。

> 这解释了字段位宽的选择：X 用 **15 位有符号**（-1024 → `0x7C00`），Y 用 **11 位有符号**（-219 → `0x725`）。上一轮把"Y 只留 11 位会导致负数被截断"列为隐患，实际上 11 位补码正好覆盖黑区负值，是**有意设计**（L2）。

#### 1.3 索引 21：尾部越界修复（L1，`0x8038FB0C–0x8038FC34` + `0x80390B68`）

```
; 从 X[20] 往前找第一个 <= 0x3FFE 的点（r7 = 该点在 19 点集内的下标）
0x8038FB14  ldr fp,[r3] ; cmp fp,#0x3FFE ; ble 0x80390B68
0x8038FBAC  udiv r8, (0x3FFF - X[j]), (18-j)   ; 均匀步长
0x8038FBDC  X[i] = X[0] + step*i
0x8038FBE4  ldr r0,[Y[i-1]] ; f2f ... i2f
0x8038FC04  slope = (Y[j+1]-Y[j]) / (X[j+1]-X[j])   ; 只算一次
0x8038FC08  fmul  slope*step
0x8038FC14  fadd  Y[i] = Y[i-1] + slope*step        ; 线性外推
0x8038FC18  bl 0x804FADA0                           ; float→int（截断）
```

- 触发条件：`X[17] > 0x3FFE`（默认表 X[17]=15872，**不触发**；`j=17 → 剩余 1 段`，只把 `X[21]` 重写成 `0x3FFF`、`Y[21]` 用真实末段斜率重算 → 与输入相同）。
- 若 C0 曲线被改成尾部 < 16382（例如用户把最后一点改成 16000），这一步会**把剩下的点按等间距摊开并线性外推 Y**，这是唯一会真正"改变 Y 数值"的地方。

#### 1.4 结论：没有"三次/切线"重采样

- `0x8038F90C` 里的 22 节点 Y **完全来自**：`19 点目标 Y`（先经 §1.5 的 7 点整形）→ 索引 3..21；`反向线性外插` → 索引 0..2。
- 真正的"三次"只出现在**求值器** `0x803887F0`（被 §1.5 的 7 点整形和 §5 的 17 点曲线调用），不参与 22 节点的生成。
- `0x803887F0` 形态（L1/部分 L2）：整数入/整数出；切线由**相邻割线平均**得到（Catmull–Rom 式三次 Hermite），两端退化线性（`0x80388A18` / `0x80388A48` 就是纯线性分支），末尾 `+0.5 → f2iz` 四舍五入。**没有**做 Fritsch–Carlson 的切线限幅（未见 min/max 夹取），所以严格说不是"单调保持"版本。

#### 1.5 目标 Y 进表前的两次 7 点整形（L1，`0x8038FA14–0x8038FA68`）

```
0x8038FA3C  ; 第 1 次：0x8038DC68(dst=sp+0x1AC, src=目标Y19, xtab=0x8062F87C, ytab=0x8062F898+28*f1, n=19, m=7)
0x8038FA68  ; 第 2 次：0x8038DC68(dst=sp+0x1AC, src=sp+0x1AC 原地, xtab=0x8062FB00, ytab=0x8062FB00+... , n=19, m=7)
0x8038DCBC  ; 每次都对 src[i] 调 0x803887F0 求值，并 min(result, 末节点值)
```
`f1/f2` 来自 `0x803C55B8` 取出的配置位域（`rsb r6,r6,r6,lsl#3` = ×7，步长 28 字节）。
默认配置下这两级是否为恒等映射，本轮**没有**验证（表是"环形窗口"，`0x8062FB00 = {764,940,1023,0,168,344,512}` 出现 1023→0 回绕）→ 归入未解项。

### 3. A/B 的精确语义（Q2）

#### 3.1 计算点（`0x8038DCE0`，第 7 参 = 22 → 21 段）

```
0x8038DD70  ldm r5,{r1,sl}          ; r5 = Y 数组：r1=Y[i], sl=Y[i+1]
0x8038DD78  ldm fp,{r2,r8}          ; fp = X 数组：r2=X[i], r8=X[i+1]
0x8038DD88  i2f(sl-r1)              ; ΔY
0x8038DD90  i2f(r8-r2)              ; ΔX
0x8038DD9C  fdiv                    ; slope = ΔY/ΔX
0x8038DE48  cmp r3,#0 ; bne ...     ; slope==0 且非末段 → 走补洞分支（用前后段平均）
0x8038DE84..                       ; 常规路径：r6=slope 不变，r8(修正项)=0
```
常规段（`slope≠0`）在 `0x8038DE84–0x8038DEB8` 归约后 `r6 = slope`、`r8 = 0`。

#### 3.2 A：Q12 斜率（L1）

```
0x8038DF54  movt r1,#0x4580          ; 0x45800000 = 4096.0f
0x8038DF58  mov r0,r6 ; fmul         ; slope × 4096
0x8038DF60  mov r1,#0x3F000000       ; 0.5f
0x8038DF64  fadd                     ; +0.5
0x8038DF68  bl 0x804FADFC            ; f2uiz（无符号截断）
0x8038DF74  str r0,[A + 4i]
```
⇒ **`A[i] = round_half_up(slope_i × 2^12)`，k = 12，无符号 16 位。**
默认曲线验证：首段 `slope=16/32=0.5 → A=2048`；末段 `slope=(1023-1019)/(16383-15872)=4/511 → A=8`。全部落在 0..65535，不会溢出。
注意 `0x804FADFC` 是**无符号** f2i（`lsls r2,r0,#1` 后符号位为 1 直接返回 0），所以**负斜率段（曲线下降）会被压成 A=0**，这是固件的实际行为，不是笔误。

#### 3.3 B：Q13 的段增益，正常恒 1.0（L1 指令 / L2 语义）

```
0x8038DF7C  lsl r8,r8,#0xd           ; 高部（整数部分）× 8192
0x8038DF80  addlt r7,r7,#0x2000      ; 低部为负时借 1.0
0x8038DF88  add r7,r8,r7             ; B = (hi<<13) + lo
0x8038DF90  str r7,[B + 4i]
```
`hi` = `f2iz(2^log(0))` 链路的整数结果，`lo` = 13 位小数部分。因为正常段 `r8 = 0`（§3.1），整条 `log2/exp2` 链路退化为常数：

```
B = (1 << 13) + lo,  lo ∈ {0, 1}  →  0x2000 或 0x2001  →  ≈1.000 (Q13)
```
（`lo` 取决于 `0x8051E9B8(0.5)` 的返回值是 0 还是 1，两条 libm 入口未完全定性；但 21 段取值**相同**这一点是 L1：r8 与 r7 在正常路径下都退化为常数。）

> **修正上一轮结论**：`CURVE_DDR_LAYOUT` 说"A 是整数部分、B 是 Q13"，实际是 **A = Q12 斜率、B = Q13 增益**；`B` 只有"零斜率段"（用前后段平均补洞）才会偏离 0x2000。

#### 3.4 C：恒 0（L1）

```
0x8038DF8C  mov r3,#0
0x8038DF94  str r3,[C + 4i]     ; 每段都写 0
```

#### 3.5 硬件公式：镜像里没有（L3）

三个 21 项数组 + `X[22]+Y[22]` 是**硬件 LUT 的输入格式**，组合公式在 ISP 里，不在 ARM 镜像内（全镜像搜 `0x1F28` / `0x20D8` 读侧为零命中，只有一个写者 `0x8049E4D4`）。

按数值量级能确定的只有：
- A 的量纲只能是 **斜率×2^12**（`ΔY/ΔX` 乘 4096）；若硬件是 `y = Y[i] + (A·(x−X[i]) >> 12)`，则 **k=12** 与之吻合。
- B 是 3 位整数 + 13 位小数，量级正好覆盖 `1.0`，最合理的解释是**段增益**（乘性），若与 A 串联则总移位 = 12+13 = **25**。
- 两者**都不是 offset**：作为截距至少需要 24 位（`Y − slope·X`，X 到 16383），B 只有 16 位，物理上放不下。

### 4. X19 的角色（Q3）

| 用途 | 位置 | 说明 |
|---|---|---|
| 生成 A/B 的 ΔX | `0x8038DD90` | `slope = ΔY/ΔX`，X 是分母 |
| 黑区步长 d | `0x8038FAC0` | `d = (X[3]−(−146))·ΔY/ΔX` |
| 尾部越界判定 | `0x8038FB1C` | `X[j] > 0x3FFE` 才修复 |
| 收尾步长 | `0x8038FBAC` | `(0x3FFF − X[j]) / 剩余段数` |
| 写进表头 | `0x8038FCB8` `bfi …,#0,#0xf` | 15 位补码 |

- **两个子块的 X 完全相同**：打包代码对 `sp+0x148` 这同一个 22 字数组读了两遍（块 1 在 `0x8038FCA8–0x8038FDF4`，块 0 在 `0x8039033C–0x803904E0`），X 从不在两遍之间被修改（`0x8038DCE0` 只写 `sp+0x4C/0xA0/0xF4`）。
- 两个子块的 Y 不同（§5），A/B 也随 Y 重算（`0x8038DCE0` 被调用两次：`0x8038FCA4`、`0x803902E8`）。
- **X 的均匀性**：C0 进来的 X19 是非均匀的，固件**原样保留**（默认 0/32/74/…/15872），只有末节点被强制成 0x3FFF。硬件拿到的就是非均匀网格。

### 5. 块 0 的固定 17 点曲线（Q4）

#### 5.1 dump（u32 × 17，已确认是 32 位字：`0x80390218 ldr r0,[pc,#-0x658]` 取指针，`0x803887F0` 内部按 `lsl #2` 索引）

```
0x8062FC5C (x): 0, 544, 680, 714, 748, 779, 811, 844, 872, 900, 927, 952, 976, 986, 997, 1009, 1023
0x8062FCA0 (y): 0, 512, 640, 672, 704, 736, 768, 800, 832, 864, 896, 928, 960, 976, 992, 1008, 1023
```

#### 5.2 形状

| 段 | 弦斜率 | y − x |
|---|---|---|
|0→544|0.941|0 → −32|
|544→680|0.941|−32 → −40|
|680→714|0.941|−40 → −42|
|714→748|0.941|−42 → −44|
|748→779|1.032|−44 → −43|
|779→811|1.000|−43 → −43|
|811→844|0.970|−43 → −44|
|844→872|1.143|−44 → −40|
|872→900|1.143|−40 → −36|
|900→927|1.185|−36 → −31|
|927→952|1.280|−31 → −24|
|952→976|1.333|−24 → −16|
|976→986|1.600|−16 → −10|
|986→997|1.455|−10 → −5|
|997→1009|1.333|−5 → −1|
|1009→1023|1.071|−1 → 0|

判定：

- **不是 gamma**：γ=2.2 编码在 x=544/1023=0.532 处应给 `0.532^0.4545 = 0.746 → 763`，实测 **512**。
- **不是 sRGB**：sRGB 编码同点为 **776**，实测 512。
- **不是线性**：线性应为 y=x，实测中段低 32~44 码。
- **是**：两端钉死在 (0,0) 与 (1023,1023) 的**近恒等色调曲线** —— 中段整体下压 32~44 码（≈3~4%，相当于 −0.5 EV 的黑位/亮度微调），高光段用 1.1~1.6 的陡斜率回勾到 1023，保证白点不丢。
- y 值几乎全落在 **32 的整数倍**（512,640,…,960）上，说明这张表是**先按输出等步长采样、再反解输入**造出来的（典型的"测量/标定 → 逆向查找表"），而不是解析函数取值。

#### 5.3 它为什么在"第二子块"里

```
0x803901D0  add r7,sp,#0x1AC      ; 起点 = Y[3]
0x80390208  add r5,sp,#0x1F8      ; 终点 = Y 末尾之后
0x80390218  ldr r0,[pc,#-0x658]   ; = 0x8062FC5C
0x80390220  add r1,r0,#0x44       ; = 0x8062FCA0
0x80390224  mov r2,#0x11          ; n = 17
0x80390228  bl 0x803887F0         ; 三次 Hermite 求值
0x8039022C  cmp r0,r4 ; strle/strgt  ; 钳到 0x3FF
0x8039023C  bne 0x80390218        ; 19 次（Y[3..21] 原地覆盖）
```
⇒ 块 1（字节 216..431）= 目标曲线本体；块 0（字节 0..215）= 目标曲线**再过一次这张近恒等色调曲线**并重算 A/B。
两块 X 相同、结构相同、只差这一层映射 —— 最小解释是**同一张表的两条消费者**（一条要"显示/取景"的观感校正，一条要"成片"的原始目标）。这属于语义推断（L2），但"块 0 = 17 点曲线的输出"是 L1。

### 6. 取景 vs 成片：subIdx 判定（Q5）

#### 6.1 subIdx 的真实链路（L1，本轮新证据）

```
0x8038F91C  bl 0x803C59F0            ; 取"实例号"
0x803C59F0  ldr r3,[r0,#0xC]         ; r3 = this->parent
0x803C59F4  ldrb r0,[r3,#0xD]        ; return parent->[0xD]  ←★ subIdx 就在这
             ↓
0x80390A18  bl 0x8017CF88(subIdx, buf)
0x8017CFC8  b  0x8049E4D4
0x8049E4F0  ldr ip,[r5, r0, lsl #2]  ; r5 = 0x813EBF50
0x8049E50C  str r4,[r2, ip]          ; dst = base[subIdx] + 0x1F28 + 4i
```

`[this+0xC]` 是父指针，由 `0x803C57F0` 写入（`0x803C5804 str r0,[r5,#0xC]`）。
父对象（0x174 B，ctor `0x8038D358`）的 `[0xD]` 由**它的**创建者写：

```
0x8038552C  strb r5(0), [r0,#0xD]    ; 兄弟 A → subIdx 0
0x80385530  strb r3(1), [r2,#0xD]    ; 兄弟 B → subIdx 1
0x80385538  strb r3(1), [r6,#0xD]    ; 第 3 个对象（0x10 B）→ 1
```

两个兄弟在同一函数（`0x803854C0`）里连续 new（`+8` / `+0xC`），**同类同大小、同构 5 个子参数（含 CIpcGammaD5）**，唯一差别就是这个字节。

#### 6.2 `0x813EBF50` 是什么（本轮关键发现，推翻"通道"说法）

```
0x804A0164  ldr r5,[pc,#0x90]        ; = 0x813EBF50
0x804A0174  str r0,[r5, r4, lsl #2]  ; ipc_mode_write_addr[idx] = addr - 0xD00
0x804A0148  ":: %s ( %d ) : error ---- ctrl_type---\n"
0x804A014C  0x806E4A0C = "d5_ipc_set_dram_addr"
0x804A0190  ":: %s ( %d ) : ipc_mode_write_addr[%d] address is %x\n"
0x804A01C0  "... IPC_WRITE_DIRECT BASE ADDRESS is 0x20810000---"
```

⇒ `0x813EBF50` = **`ipc_mode_write_addr[4]`**，由 `d5_ipc_set_dram_addr(mode, addr)` 填充。
`0x804A0138  cmp r0,#2 ; bls` + `cmp r0,#3 ; beq（直写 0x20810000）` → **合法 index 只有 0/1/2/3**，4 个模式缓冲。

所以：**subIdx 不是颜色通道，也不是"4 通道实例"，而是 IPC 模式号**（上一轮"4 通道 × 每个实例一次"的说法应废弃）。设置这三个缓冲的唯一两个函数是 `0x8012A068` 与 `0x80137E88`，二者都对 `mode=0,1,2` 各下发一次。

#### 6.3 判定

- CIpcGammaD5 只有 **subIdx 0** 与 **subIdx 1** 两个实例（`strb 0` / `strb 1`），第三个模式（2）没有动态 gamma 实例，只由 `IpcParam::InitGroup(2)` 铺默认表。
- 两个实例结构完全对称、都由同一个宿主创建（`0x803854C0` → `+8` / `+0xC`），宿主自身被 **7 个静态初始化点** 各创建一次（`0x8029B874 / 0x802A5B20 / 0x802B4388 / 0x802C3F20 / …`），即"每个后端一套"。
- 也就是说这套 0/1 是**"模式 0 / 模式 1"** 的固定绑定，顺序与后端注册顺序绑定。

**结论：取景（liveview）= subIdx 0。证据强度 L2（中）。** 依据：

| 依据 | 强度 |
|---|---|
| subIdx 只做"模式缓冲索引"，语义不是通道（字符串 + 函数名 + index 范围） | L1 |
| 两个实例是同一宿主的 (0,1) 兄弟，对称、同构 → 只能是"两种消费场景" | L1 |
| 定序方向（0=view）来自 IPC 模式表的惯例顺序（view/still/movie）与 InitGroup 先铺 group0 的顺序 | **L2，弱**：镜像里没有把 0/1/2 与 view/still 字符串绑定的表（`ipc_mode_write_addr` 附近无枚举名） |
| 消费侧（ISP）不在本镜像 | 无法静态证明（L3） |

#### 6.4 上机 5 分钟即可定死（建议）

1. 取景状态下读 `u32[0x813EBF50+0]` 与 `[+4]`（记 `B0/B1`），grep `d5_ipc_set_dram_addr` 的 trace 看哪个地址被赋给哪个 mode。
2. `dump B0+0x1F28 432B` 与 `B1+0x1F28 432B`，比对**块 0 的 Y[22]**：若其中一块的 Y 等于"19 点曲线过 17 点表"的结果（中段整体低 ~32~44 码），该块就是带显示校正的那条；对另一块做同样比对。
3. 在取景下把 C0 的 Y 改成明显不同的曲线，观察哪一块先变 ⇒ 即 liveview 的 subIdx。
   （`IpcParam::InitGroup` 只在初始化时铺一次，运行期改写需走 `0x8038F90C` 的虚表 +0x18 入口。）
