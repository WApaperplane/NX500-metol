### 1. 硬件判决

#### 1.1 只有一级

p7 对 3DLUT 块的全部写入（`P7_3DLUT_PATHS` §4.2 全镜像 grep）：

```
+0x000  OnOff
+0x004  Cfg      bits[1:0]=SelCbCr_ch  bits[5:4]=SelLUT  bit8=LUT0 fmt  bit12=LUT1 fmt
+0x008  Pulse    bit8=写方向(rw_Start=1)  bit4=读方向(rw_Start=2)
+0x00c  LUT0 数据地址
+0x010  LUT1 数据地址
```

**五个寄存器，没有长度、没有维度、没有第二级。** 长度硬编码在 DMA 控制器里（4913×4B）。

#### 1.2 LUT0/LUT1 是 bank，不是串级

`libudd5` 写序列（`sub_3a888`）：

```c
_udd_ep_3dl_reg_OnOff(1);
_udd_ep_3dl_reg_Acc_OnOff(0);  _udd_ep_3dl_reg_Acc_OnOff(1);   // 开访问窗口
switch (c->mode_at_0x10) {
case 0:  SetAddress(cfg->f8, c->f4); SetColorFormat(c->f8, …); break;   // → +0x0c
case 1:  SetAddress(cfg->fc, c->f4); SetColorFormat(cfg->fc, …); break; // → +0x10
case 2:  /* 两个地址都设 */                                              break;
}
rw_Start(1);   // bit8 脉冲 = 一次 DMA
```

`SelLUT` 写的是 `Cfg bits[5:4]`，2 bit 宽，值域 `{0,1,2}`，语义 = "选哪张表"。**一次 DMA 只搬一张表**，`case 2` 只是把两个地址寄存器的入口都打开，不是"跑两遍"。

#### 1.3 三条软件路径共用同一块硬件

`CBackend_3dlut_View` / `_Still` / `_CS` 三个 vtable 都落到 `0x2082b000`。ISP 链上**没有第二个 3D LUT 阶段**可以挂第二张表。

⇒ **要在设备上做"两张表顺序作用"，只能改 p7 在链里插第二个 pass**，而链上没有这个位置。这不是"没找到"，是"不存在"。

### 2. 三种"分离"的技术含义

| 形态 | 两张表在哪 | 是否串联 | 硬件可行 | 用途 |
|---|---|---|---|---|
| **A 设计期分离** | PC 浮点域 | 是（但只在内存里） | ✅ 无关硬件 | 独立调 tone / color；最终合成单表 |
| **B 双槽分发** | View4 槽 + Still6 槽 | 否（各走各链路） | ✅ 已实证（10-18） | 预览表 ≠ 成片表 |
| **C 双 bank 热切** | LUT0 SRAM + LUT1 SRAM | 否（互斥生效） | ◐ 待验（§4.2） | A/B 秒切、零重载 |

"级联"（真·两张表一前一后作用在同一像素上）**不在可行集里**。

### 3. 数值实验：两级分解到底损失多少

#### 3.1 方法

- 取 `looks/` 下的 native 表（CrCbY-BT601-full-v1，有 `encoding.json` 哈希校验）
- 只统计**合法输入格点**（`ycc_to_rgb(clip=False)` 三通道都在 [0,255]）：**971 / 4913 = 19.8%**
  （其余 80.2% 是 sRGB 域外的外推填充，算进去会污染统计——上一版 `LUT_PHYSICAL_FILM` 的"80.5% 越界"在此复现）
- 分解：
  - **T 级**：只改 Y，曲线取中性轴（`Cr=Cb=128` 的 17 点响应），色度直通
  - **C 级**：只改 CbCr。分两种构造：
    - `naive`：C 表直接在原始格点上取 f 的色度（用错 Y 位置）
    - `compensated`：C 表在 **T 的输出域**重建（`C(y) = f(T⁻¹(y))`），理论上应精确复现 f
- 误差 = RGB 域三通道**最大绝对误差**（0–255 尺度）

#### 3.2 结果

| 表 | Y 的色度耦合（同亮度跨色度 std） | naive 均值 | **compensated 均值** | compensated p95 | max |
|---|---:|---:|---:|---:|---:|
| fuji_velvia50 | **5.3** | 9.5 | **7.2** | 20.3 | 34 |
| brand_teal_orange | 7.9 | 12.1 | **8.2** | 24.2 | 68 |
| kodak_portra400 | 12.5 | 26.1 | **14.8** | 40.4 | 91 |
| fuji_pro_neg_std | **18.7** | 31.7 | **26.1** | 68.7 | 92 |

#### 3.3 读法

- **补偿式比朴素式好 20–45%**，但**没有一项进入可接受区**（摄影上 <3 才算无损）
- 损失来源是硬性的：C 级的 Y 分辨率仍只有 17 级，而色度对亮度的依赖很强（spread 24–40/17 级 ≈ 每级 2.4）
- **表的"亮度-色度耦合度"直接决定分离代价**：Velvia 类（主要做色相旋转）耦合低、可分离性最好；Portra / ProNeg 类（负片密度混合）耦合高、分离必然坏

⇒ **结论：17³ × 2 的串联在强风格表上不成立。** 想要两级，必须两级都在浮点域，最后只落地一张表（即形态 A）。

### 4. 可行的两条路

#### 4.1 形态 B：双槽分发（已具备，10-18 实证）

| | View 链路 | Still 链路 |
|---|---|---|
| 登记表 | `View4 @ 0x803837F0`（4 项） | `Still6 @ 0x80382C5C`（6 项） |
| 切换方式 | 改 4 字节项 + 半按 | 改 4 字节项 |
| 表来源 | 槽池任选（103 个 0x4D00 槽） | 同左 |

**两张表可以完全不同、同时生效、互不干扰。** 这是唯一"真·双 LUT"的现有形态。

用途（需明确 UI 语义）：
- 预览表 = 保守版（低对比、暗部不死黑，取景器看得清）
- 成片表 = 完整版（打印级曲线）
- 代价：**所见非所得**，必须告诉用户"取景器只是预告"

#### 4.2 形态 C：双 bank 热切（待验证，建议先做）

前提事实：
- p7 只写 `+0x00c`（LUT0 地址），**不碰 `+0x010`（LUT1）** ⇒ LUT1 内容装一次就常驻
- p7 半按会把 `SelLUT` 写回 0（E3 守护记录的 6 次"抢回"就是这件事）

**待验证的唯一问题**：只写 `Cfg bits[5:4]`（不触发 DMA）能否立即切换画面？

- 若**能** ⇒ 两张表常驻，写 4 字节即切换，A/B 对比零延迟（摄影调色最实用的功能）
- 若**不能** ⇒ 切 bank 必须伴随一次 load（1.6 MB/s × 19.7 KB ≈ 12 ms，仍可接受）

E1（10-09）观察到 `sel=1` 后 `Cfg=0x1110` 且画面变化，但当时 `op_init` 后面还跟了 `load`，**两个变量没分离**。这是本轮唯一值得上机的实验，零风险（只写 Cfg，可立即写回）。

#### 4.3 形态 A：设计期两阶段（当前 `film_physics` 已在做）

neg（负片）→ print（相纸）两级，**在 numpy 浮点域复合**，最后一次性量化成 17³ 单表。

这是唯一精度无损的两级结构。它回答的是"设计上要不要分开"，不是"设备上能不能分开放"。

## 2. 双 LUT 各自强度：三种语义、实测代价与落地方式（2026-11-02）

> 来源：`DUAL_STRENGTH_2026-11-02.md`（已归档至 `docs/archive/`）

> 需求（木一）：混合想做成**两张 LUT 各自带强度**，而不是现在这样只有一个混合比例。
> 本文只回答两件事：**「两个强度」在数学上到底有几种解释**，以及**哪一种能用最小改动落地**。
> 全部离线静态验证，未上机、未写槽。

---

### 0. 结论

| # | 命题 | 依据 |
|---|---|---|
| 1 | 「两个独立强度」有三种自洽语义：M1 偏移相加、M2 顺层覆盖、M3 归一加权 | §1 |
| 2 | **M2（松下图层式）顺序敏感**：A/B 互换后平均差 7 级，双 100% 差 28–30 级 | 实测 |
| 3 | **M1（两个偏移相加）会溢出**：α+β>1 时最多 692/4913 个节点越界（14%），是死黑死白 | 实测 |
| 4 | **M3 零溢出、零顺序依赖**，且 α+β≤1 时与 M1 完全等价（差 ≤1 级） | 实测 |
| 5 | ⇒ **M3 是唯一安全又无副作用的语义** | — |
| 6 | **M3 = 现有 `mix` + `strength` 两次调用**，一个新二进制都不用写 | qemu 逐字节验证 |
| 7 | 换算后 M3 等价于「**A/B 比例 r** + **总强度 s**」，两者正交 | 数学 + 实测 |
| 8 | 已落地：`lut.sh blend` + 混合态双强度；长按/滑动保持原样 | 46 + 24 + 19 全绿，已部署上机 |

### 1. 三种语义

设基准 B0 = 原厂 A17，两张 look 为 A、B，强度 α、β ∈ [0,1]：

| 模型 | 公式 | 直觉 |
|---|---|---|
| **M1 偏移相加** | `T = B0 + α(A−B0) + β(B−B0)` | 两张表各按自己的强度**贡献偏移**，互不覆盖 |
| **M2 顺层覆盖** | `T = mix(mix(B0, A, α), B, β)` | 先按 α 打 A，再按 β 盖 B（图层 / 松下 opacity 语义） |
| **M3 归一加权** | `T = B0 + (α(A−B0) + β(B−B0)) / max(1, α+β)` | 两张表按强度**加权**，总权重超 1 就归一 |

三者都满足：α=1,β=0 → 纯 A；α=0,β=1 → 纯 B；α=β=0 → 原厂。

#### 1.1 溢出（clamp 之前的越界节点数，总计 4,913）

只统计**混合导致的**越界。直接数「输出 Y 贴 0/255」是错的 —— 胶片表本来就把黑白端点压死，`kodak_portra400` 自己有 533 个这样的节点。

| 组合 | 模型 | α | β | Y 越界 | CbCr 越界 |
|---|---|---|---|---|---|
| portra400 × teal_green | M1 | 1.0 | 1.0 | **140** | **144** |
| portra400 × mono_acros | M1 | 0.5 | 1.0 | **454** | 22 |
| portra400 × mono_acros | M1 | 1.0 | 1.0 | **692** | **211** |
| 任意 | M2 | 任意 | 任意 | 0 | 0 |
| 任意 | M3 | 任意 | 任意 | 0 | 0 |

**M1 的溢出只发生在 α+β>1**：只要两者之和不超过 100%，它也是零溢出（这时它和 M3 是同一个公式）。

#### 1.2 顺序依赖（A/B 互换后的平均通道差，单位：8 位级）

| 组合 | 模型 | α=β=0.5 | α=1, β=1 |
|---|---|---|---|
| portra400 × teal_green | M1 / M3 | 0.00 | 0.00 |
| portra400 × teal_green | **M2** | **7.06** | **28.28** |
| portra400 × mono_acros | **M2** | **7.55** | **30.16** |

M2 在双 100% 时相当于**换了一张画** —— 用户把 A、B 换个位置，成片就变了，而 UI 上没有任何提示。这是它作为默认语义的致命伤。

#### 1.3 关键色读数（α=β=0.5，中灰 / 肤色 / 白点）

| 组合 | 模型 | 灰 128 | 肤色 | 白 245 |
|---|---|---|---|---|
| portra400 × teal_green | M1 = M3 | (132,139,145) | (203,148,118) | (242,243,245) |
| portra400 × teal_green | M2 | (126,131,137) | (196,142,114) | (241,242,245) |
| portra400 × mono_acros | M1 = M3 | (140,140,142) | (185,154,135) | (247,247,247) |
| portra400 × mono_acros | M2 | (132,132,134) | (179,148,132) | (246,246,246) |

差异方向一致（M2 总是更靠近 B），量级 5–7 级 —— 不是误差，是语义差别。

### 2. 为什么 M3 = 现有两个动词的组合

把 M3 拆开。令 `s = min(α+β, 1)`、`r = β/(α+β)`：

```
M_AB(r) = (1−r)·A + r·B                    ← 就是现在的 mix A B r
M3      = B0 + s·(M_AB(r) − B0)            ← 就是现在的 strength · s
```

**两次 `lutmix` 调用，一个新二进制都不用写。** 两个动词（`mix` / `strength`）11-01 就已经在 `lut.sh` 里了。

#### 2.1 验证（`test_server/lutpipe/test_dual_strength.py`）

qemu 下真跑两次 `lutmix.arm`，与 Python 参考逐字节比对：

| 检查 | 结果 |
|---|---|
| mix→strength 两步 == 两步参考（6 组 α/β） | 全等 |
| 与理想单步值（`base + s·(mid−base)`）的差 | ≤ 1 级（两次 8 位取整的极限） |
| α+β ≤ 1 时 M3 与 M1 的差 | ≤ 1 级 |
| s=0 必须逐字节回到原厂表 | 通过 |
| s=1000 必须等于纯 mix 结果 | 通过 |

#### 2.2 代价

两次调用 = 多一次 19,712 B 的读写。中间表放 `/tmp`（内存，不产生 exFAT 碎片），实际耗时在 ARM 上是毫秒级 —— 对比现有 `apply` 的 0.5 s（`.cube` 转换）完全不是瓶颈。

### 3. UI 怎么摆（720×208 不能多一行）

MIX 态现在只有一条滑杆（强度）。要两个强度，且**不能新增行** —— 按钮行 `y=123/149` 被测试钉死。

方案：**一条滑杆 + 焦点切换**。

| 元素 | 行为 |
|---|---|
| 底部状态行 | `A 60%   B 25%   -> 比例 71% / 强度 85%   退出即应用` |
| 标题 | `LUT / 混合 · A` 或 `· B`，直接标出焦点 |
| 左右键 | 混合态：选 A / 选 B 焦点；其余态：照旧翻页（`ACT_LEFT`/`ACT_RIGHT` 与上下分开绑） |
| 上下键 | 换条目（混合态里也能翻，这是设 A/B 时唯一需要的导航） |
| 滑杆 / 右上拨盘 | 调**当前焦点那个**的强度（拨盘 5%/格） |
| 按钮行四格 | `设为A` `设为B` `应用混合` `退出` |
| 翻页 | 滚条拖动（跨全库最快）、上下键、EV 拨盘、右上拨盘 |

用户看到的还是「两个强度各一根」，内部换算成比例和总强度 —— 换算对用户不可见，但**结果可预测**：双 100% 得到的是两张表的中点全强度，不是死黑死白。

#### 3.1 A/B 在哪标 —— 试过搬出去，实机不行，退回来了

曾经把标记搬到浏览态长按（「翻到哪标到哪」听起来最省事），**实机一按就跳**：

> 列表是「选中项居中」的 5 项窗口（`first = selected - win/2`）。手指按下的一瞬间该项被选中，整排立刻平移，手指底下换成了另一条 —— 长按根本对不准，还把原来的「长按进编辑态」挤掉了。

所以定稿是：**长按还给编辑态，A/B 回混合态用按钮设**。原来那个「跨度大不好设」的痛点，靠两件事解决：

| 手段 | 作用 |
|---|---|
| 滚条拖动 | 一次跨全库（68 项 → 700px 轨道，拖到哪算哪） |
| 滚条上 A（绿）/ B（橙）两个刻度 + 列表 `[A]`/`[B]` 前缀 | 跨页也看得见两个端点在哪，不用记 |

**一并删掉的还有左右滑动切项**（原来「滑得远切得快」）：它和「选中即居中」的平移叠在一起，手指刚落下整排就动，再滑一次直接把目标甩掉。删掉之后翻页只剩滚条 + 上下键 + 拨盘 —— 实测够用，而且点选本身也稳了。

#### 3.2 必须写进 UI 的一句话

> 两个强度之和超过 100% 时，效果会被等比例压缩（不会叠加到溢出）；**退出混合即应用**。

这不是妥协，是 M1/M2/M3 任何双参数模型都逃不掉的耦合：两张表的偏移向量并不两两正交，同时推满必然要有个"怎么办"。选归一，是因为它唯一可预测。
