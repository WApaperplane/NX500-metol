## 0. 一句话

编译链已完全打通（产物 ELF 特征与你那只探针一致）；但**现在这台机器上，任何独立进程的
`eglInitialize` 都返回 `0x3008 (EGL_NOT_INITIALIZED)`**——包括你那只原本跑通的 `gpu_probe.arm`。

## 1. 复现结果（三次尝试，逐级深入）

| # | 命令 | 结果 |
|---|---|---|
| 1 | `./gpu_probe.arm` | `/usr/lib/libEGL.so.1: undefined symbol: native_buffer_get_bo` |

| 3 | 同上 + `EGL_PLATFORM=fbdev` / `drm` / 不设 | **三组全部 0x3008** |

★ 第 1 条说明：**你的探针里没有 preload**（源码确认），当时能跑通必然依赖了外部条件。

## 2. 根因假设：DRM master 被 Enlightenment 独占

```
/dev/dri/card0   crw-rw---- root video 226,0
/dev/fb0         crw-rw---- root video  29,0
/dev/mali        crw-rw---- root video 10,118    ← 可 open
/dev/ump         crw-rw---- root video 253,0     ← 可 open

持有者：enlightenment (PID 200, 用户 app)
        fd 19 -> /dev/ump
        fd 20 -> /dev/mali
        fd 21 -> /dev/dri/card0
另一个 root 进程也持有 /dev/dri/card0 与 /dev/ump
```

Mali r3p2 的 `eglInitialize` 在建立 display 连接时要拿显示资源（DRM 或 fbdev），
被现有 master 占着就拿不到 ⇒ `EGL_NOT_INITIALIZED`。pbuffer 是离屏的，但
`eglInitialize` 本身仍然要先过这一关。

## 3. 已打通的编译链（可复用）

相机 glibc 2.13 + Ubuntu 24.04 的 gcc 13 组合，直接用 `-ldl` 拿不到 `dlopen`
（glibc 2.34 起 dlopen 并入 libc，libdl 变空壳）。可行做法：

1. 从相机取实体库：`/lib/libdl-2.13.so`（9,820 B）→ `test_server/gpu/syslib/`
2. 链接时把它当输入文件，并放行 shlib 未定义符号（`_dl_sym@GLIBC_PRIVATE` 等由运行时 ld.so 提供）
3. `-nostdlib` 下 libgcc 的除法辅助要 `raise`，自备空桩

```sh
arm-linux-gnueabi-gcc -O2 -nostdlib -fno-builtin -Wl,-e,_start \
    -Wl,--allow-shlib-undefined \
    -o gpu_bench.arm gpu_bench.c syslib/libdl-2.13.so -lgcc
```

产物校验（与 `gpu_probe.arm` 一致）：

```
NEEDED  : libdl.so.2
VERNEED : libdl.so.2 -> GLIBC_2.4
size    : 10,748 B
```

★ 这条链子本身就是今天最有价值的产出——**下次不用再从 `-ldl` 的坑里爬一遍**。

## 4. 基准程序（已就绪，未取得数据）

`test_server/gpu/gpu_bench.c`：EGL pbuffer，三种 shader（copy / 3×3 色彩矩阵 / 1D LUT），
三种输出尺寸（128 / 256 / 512），每段用 `glFinish` 收口后计时：

```
BENCH <size> <op> <upload_us> <draw_us> <read_us>
```

- 计时走 `clock_gettime(CLOCK_MONOTONIC)` 系统调用（syscall 263），不引入 libc
- 源图 512² RGBA（BSS 压到 2 MB）——因为相机常驻内存只剩 **6,004 KB**
- 已内置 `dlopen("libnative-buffer.so", RTLD_GLOBAL)` 再载 EGL 的顺序
