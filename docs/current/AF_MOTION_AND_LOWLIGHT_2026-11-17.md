# AF 的画面判据：低光、预测与主脸打分（2026-11-17）

> **2026-11-20 重写**：原 `AF_LOWLIGHT_CHAIN_2026-11-17.md`（392 行）与
> `AF_MOTION_LEVERS_2026-11-17.md`（818 行）已归档到 `docs/archive/`。
> 本文只保留判定与可改点。性质：纯静态，未连相机；镜像 `p7_wrapped.elf`，地址口径见
> `AF_ADDRESS_AND_AE` §0（`runtime = chunk + 0x80000000`）。

---

## 0. 三条结论

| 问题 | 答案 | 可改否 |
|---|---|---|
| 低照度会禁用相位吗？ | **不会**。相位入口 `0x34857c` 的全部条件里没有 LV/ISO 比较 | — |
| 低照度会怎样？ | 有低照度分支，但作用于**滤波器 / 膝点**（`DecideAfKneeMode` `0x335cf0`，写 IQ `0x40011` @`0x335eb0`）；表现为"低照度下停在粗扫不前进"（串 `0x74ea8c`，引用点 `0x347320`） | — |
| 预测阶数能改吗？ | 能。**算法号是硬编码实参**不是字段，改 1 条指令即可切一阶 | ✅ |

## 1. 低光：照度只碰滤波器，不碰门控

| 命题 | 判定 | 依据 |
|---|---|---|
| 照度参与 AF 门控 | **部分有**：低照度分支作用在滤波器/膝点，不在相位许可 | `DecideAfKneeMode` `0x335cf0`；`KneeMode(LOW_LUMINANCE)` 串 `0x74b9a0` |
| 低照度 → 禁用相位 | **无** | 相位入口 `0x34857c` 全条件无 LV/ISO 比较 |
| 低照度 → 延长扫描 | **无直接证据**；只有"低照度下停在粗扫" | 串 `0x74ea8c` → `0x347320`（函数 `0x3470fc`） |

> 这与 `AF_ADDRESS_AND_AE` §2.2 一致：AE 影响 AF 的唯一正式路径是 LV+ISO → 滤波器参数
> （`0x20002/0x20004/0x20007/0x2000C`），不是改门控。

**这一轮的地址修正**（差 `0x1000`）：`0x34470c→0x34570c`、`0x3406dc→0x3416dc`、`0x34a13c→0x34b13c`，
而 `0x2f0ce4`「相位许可六输入」**无法复现**（`0x2f1ce4` / `0x2efce4` 都对不上）。

## 2. 预测阶数是硬编码实参（最小改动点之一）

```
0x33bfcc  ExecuteExposurePredictContiH
  0x33bff0  mov r1, #1        ← 算法号，硬编码
  0x33bff8  bl  0x36f634      ← 分派器
              0 → 0x36f13c  二阶路径
              1 → 0x36f4f0  一阶路径
```

`0x33bfcc` 的调用点只有两处，都在 AF 序列的 drive 步：`0x2f4840`、`0x2f4908`。

**可改**：三帧历史 AF 结果已在共享环形缓冲里，**无需新增状态**，改 1 条指令即可。

## 3. 800ms 常量被两个方向共用（最小改动点之二）

| 方向 | 地址 | 寄存器 |
|---|---|---|
| 获得方向 | `0x2f6cfc` | `r8` |
| 丢失方向 | `0x2f6dd4` | `r8`（与上面**共用**同一个值） |
| 常量 | `0x2f6c8c` | — |

关键发现：**丢失路径的 `r6` 完全空闲**，且 `r5` 与 `r4` 是同一个 GAF 指针（冗余装载）。

**最小改法**：1 条指令把 `cmp r8,r2` 改成 `cmp r8,r2,lsl #3`（800 → 100ms），
`stage==2 → 0` 的语义自动保持。

## 4. 主脸打分：只有几何，没有记忆

```
score = 6 × 距离名次 + 3 × 面积名次，取最大
```

- 距离是**未归一化的欧氏平方（像素²）**；
- 名次由冒泡排序（降序）+ 反序编号得到；
- **没有任何帧间平滑、身份保持或历史偏置**。

| 项 | 地址 |
|---|---|
| 打分 | `0x143740` |
| 排名 | `0x14360c` |
| 结果写入 | `0x1438c4` → `ctx[0x398]` |

**可改**：加惩罚项需要 2 条指令 + 1 个 4 字节代码洞；**不需要新增全局变量**
（复用 `ctx[0x398]` 的旧值即可）。

> 这与 `NX500_AF_STATIC_OVERVIEW` §0 的第 1 条呼应：固件里已有 `C3AStateLock*` 的 face-box hold，
> 所以"身份保持"不必从打分函数动刀 —— 这里加惩罚是"更快锁定"，hold 是"锁住不放"，两条路都在。

## 5. 两处必须记住的地址修正

| 旧说法 | 正确 | 影响 |
|---|---|---|
| GAF 基址 `0x816d429c` | **`0x81550408`** | `0x816d429c` 是 **trace/log 上下文**（`0x34cbd0` / `0x34ca08` / `0x34ccf4` / `0x34cc78` 的第 1 实参）。凡把它当 GAF 的结论，字段偏移全部要复核 |
| `0x349ca8` 是"预测分派器" | 不是。它只是 AF 事件状态机里事件 `0x306` 的一个 case；真分派在 `0x36f634` | 改预测阶数要改 `0x33bff0`，不是 `0x349ca8` |

GAF 基址来源：常量池 `0x2f6e4c`（`ldr r4,[pc,#0x1d0]` @ `0x2f6c74`），`[r4,#0x5c]` 即"内部执行阶段"。

## 6. 边界

1. "低照度不禁用相位"是**静态条件穷举**的结论，不含运行时观测。
2. 预测阶数与 800ms 的可改性都是**指令层面可行**，未有补丁、未上机、未测收益。
3. 主脸惩罚项的"2 条指令 + 4 字节洞"是空间估算，未验证插入后跳转范围。
