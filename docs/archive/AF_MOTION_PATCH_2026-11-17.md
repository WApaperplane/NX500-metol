## 一、任务一：NG=8 / OK=4 / small=4 三个初值的位置

### 1.1 结论（先给答案）

三个初值不是散落在算法里的立即数，而是**AF 管理器构造函数一次性写入全局 AF 上下文的三个相邻 int 字段**：

| 参数 | 默认值 | 字段（绝对地址） | 字段（相对 GAF=`0x81550408`） | 初值写入指令 | 文件偏移 |
|---|---|---|---|---|---|
| `ng`（# of successive NGs to stop tracking） | **8** | `0x8155044C` | `GAF+0x44` | `0x8029B558` `mov r2,#8` → `0x8029B56C` `str r2,[r5,#0x22c]` | `0x29C558` / `0x29C56C` |
| `small`（# of small object chatterings） | **4** | `0x81550450` | `GAF+0x48` | `0x8029B4F8` `mov r3,#4` → `0x8029B500` `str r3,[r5,#0x230]` | `0x29C4F8` / `0x29C500` |
| `ok`（# of OKs to start next tracking） | **4** | `0x81550454` | `GAF+0x4C` | 同上 `r3=4` → `0x8029B504` `str r3,[r5,#0x234]` | `0x29C504` |

- 函数入口是 `0x8029B4E4`（`push {r3,r4,r5,r6,r7,r8,sl,lr}`），`0x8029B4E8` 是装入 `r5` 的第一条指令
  （`ldr r5,[pc,#0x3b0]`，字面池 `0x8029B8A0 = 0x81550220`）；
  `0x81550220 + 0x22C = 0x8155044C = GAF+0x44`（三条指令的基址与偏移互相印证，不存在歧义）。
- 该函数只有一个调用者 `0x802AEC80`（`bl 0x8029B4E4`），是 AF 管理器的一次性构造入口（同函数内还调用
  `0x802c01bc`（AF 算法单例 getter）、`0x802b7954`、`0x802b9b3c` 等 20 余个子系统构造器，见 `0x8029B5D8`–`0x8029B664`），
  因此这是**上电/子系统初始化时的默认值**。

### 1.2 证据链（消费端反推，四段全部落地）

**(a) 调试命令的"打印"分支直接证明了三个字段的顺序**
`0x802FA0C0`：

```

802fa0bc  ldr r4, [pc,#0x180]      ; 81550408  GAF
802fa0c0  add r1, r4, #0x44        ; r1 = &GAF[0x44]
802fa0c4  ldm r1, {r1, r2, r3}     ; 一次取出 3 个 int
802fa0c8  ldr r0, [pc,#0x2b8]      ; 80743a60 "Tracking Control Parameters: ... ngs ... chatterings ... oks ..."
802fa0cc  bl  #0x80011e70          ; printf
```

→ 三个相邻 int 从 `GAF+0x44` 起，参数顺序 `(ng, small, ok)`，与格式串里 `%d` 的排列一致。

**(b) 调试命令的"写"分支给出参数名与字段的一一对应**
`0x802FA1D4`（`argc > 6` 时进入）：

```
802fa1d4  ldr r0, [r5,#0x10]      ; argv[3]
802fa1d8  bl  #0x80507dac         ; atoi
802fa1e0  str r0, [r4,#0x44]      ; ng
802fa1e4  ldr r0, [r5,#0x14]      ; argv[4]
802fa1e8  bl  #0x80507dac
802fa1ec  str r0, [r4,#0x48]      ; small
802fa1f0  ldr r0, [r5,#0x18]      ; argv[5]
802fa1f4  bl  #0x80507dac
802fa1f8  str r0, [r4,#0x4c]      ; ok

注意：`tracking` 分支**本身没有任何范围校验**（`argc > 6` 就直接 `atoi` 后落盘，随后回到 `0x802FA0C0` 把三个值原样打印一遍）。
旁边 `0x802F9FA4`（`sub r3,r1,#3; cmp r3,#0x1D`）的那组校验属于**同级的 `group` 子命令**，作用对象是 `GAF+0x3C`（分组采样数）与 `GAF+0x38`（最大采样数），与 `ng/ok/small` 无关，不要混淆。

**(c) 全镜像写入点扫描（数据流：只统计基址确实被装成 `0x81550408` 的 store）**

对 `GAF+0x44/0x48/0x4C` 的写入**只有两处**（池装载 `ldr rX,[pc,#..]` 与 `movw/movt` 两种基址构造形态均已扫过；
`str rX,[sl,#0x4c]`、`str rX,[sp,#0x48]` 这类同偏移但异基址的命中已剔除）：
1. `0x8029B4F8`–`0x8029B56C`（构造函数默认值，本报告结论）；
2. `0x802FA1E0`–`0x802FA1F8`（调试命令覆盖，见 (b)）。

没有第三方覆盖点，`CAFData`、`0x81561CF4` 单例、`0x34E4A8` 状态机都与这三个字段无关——上一轮"从单例 vtable 找"的方向可以正式关闭。

**(d) 三个值随后被拷进 OT 追踪器对象，且 ng 的消费分支已定位**

拷贝点 `0x8034E9C8`（函数入口，`r0` = 追踪器对象）：

```
8034e9ec  ldr r1, [r3,#0x44]      ; ng
8034e9f0  ldr r2, [r3,#0x4c]      ; ok
8034e9f4  ldr r3, [r3,#0x48]      ; small
8034e9f8  str r1, [r0,#0x150]     ; tracker->ngTh
8034e9fc  str r2, [r0,#0x154]     ; tracker->okTh
8034ea00  str r3, [r0,#0x158]     ; tracker->smallTh
```

消费点（**这才是"AF 处理对象的比较分支"**）：

```
; ng：连续 NG 计数到阈值 → 停止跟踪
80351588  ldr r2, [r5,#0x10c]      ; ngCount
8035158c  ldr r0, [r5,#0x150]      ; ngTh   ← 来自 GAF+0x44

8035159c  bge 0x803515dc           ; ngCount >= ngTh → 0x803512b4（停跟踪）

8035127c  ldr r2, [r4,#0x154]      ; okTh   ← 来自 GAF+0x4c

80351284  blt 0x803511a8           ; count < okTh → 继续等

补充：`0x8034EA08` 有一条**例外分支**——当 `GAF[3] & 0x20 != 0`，或 `GAF[0x5c] > 3` 时，三个阈值被强制写成
`ngTh=0x1E8480(2,000,000) / okTh=0 / smallTh=0`，即"等价于关闭多目标追踪的 NG/OK 判据"。
（`GAF+0x5C` 是 AF 模式字：按 `AF_ADDRESS_MAP` 的结论，`1=SLOW-AF`、`2=S0-AF`，`>3` 属于其它模式。）
**改默认值时要注意这条旁路**：它绕过 `0x8029B4F8` 写入的值，只影响 `GAF[3]&0x20` 或 `GAF[0x5c]>3` 的模式。

### 1.3 如果要改默认值（顺带给出，非本次要求）

| 目标 | 改哪里 | 原字节 | 建议字节 | 说明 |
|---|---|---|---|---|
| NG 8→N | `0x8029B558` `mov r2,#8` | `08 20 a0 e3` | `0N 20 a0 e3`（N≤255） | 独占寄存器，安全 |
| OK 4→M | `0x8029B504` 的源寄存器 | — | — | **不能只改 `0x8029B4F8`**：该 `mov r3,#4` 同时供 `small`（`0x8029B500`）与 `ok`（`0x8029B504`）使用；要单独改 OK，需把 `0x8029B504` 换成 `str r2,[r5,#0x234]` 之类，或新增一条 `mov` |
| small 4→S | `0x8029B4F8` `mov r3,#4` | `04 30 a0 e3` | `0S 30 a0 e3` | 会同时改掉 OK，见上 |

> 约束：构造函数侧**没有任何范围校验**，调试命令侧对 `tracking` 也不校验（只有 `group` 子命令才校验 3..32）。因此改默认值只需保证 `1 ≤ 值 ≤ 255`（字节立即数可编码），但建议保持 `ng ≥ 2`、`small ≥ 1`，否则多目标追踪会退化为"一帧即停/立刻抖动"。

### 2.2 设计思路：用"数学等价改写"腾出空间，做到**零代码洞**

上一轮的结论是"需要 2 条指令 + 1 个 4 字节洞"。本次发现**不需要洞**，理由：

1. `3a + 6d` 可以改写成 `3 × (a + 2d)`：
   `add ip, ip, r3, lsl #1`（`ip = a + 2d`）＋ `add ip, ip, ip, lsl #1`（`ip = 3a + 6d`），
   由 3 条指令降为 2 条（数值完全相同，已验证 20000 组随机名次数组 `K=0` 时输出 100% 一致）。
2. 计数器 `r1` 可以完全消除：`r2` 本身就是 `i*4`，用 `cmp r2, r8, lsl #2` 直接做终止条件；
   `i` 只在 `movhi r7, r3` 处需要，用 `lsr r3, r2, #2` 现算即可。
   省掉 `mov r1, sl`、`add r1, r1, #1`、`cmp r1, r8` 三条，补回 `cmp/lsr/cmp` 三条。

净效果：**循环指令条数不变（14 条）**，惩罚项完全塞进原有指令槽，`0x1438C0` 反而空出 4 字节。

顺序关键点：`cmp r2, sb, lsl #2` 会破坏标志位，所以必须**先**做惩罚比较、**再**做 `cmp ip, r0`，让 `movhi`/`movhs` 吃到正确的标志。中间只允许夹不写标志的指令（`lsr` 不带 S，安全）。

### 2.3 字节级补丁

**K 值只需改第 7 条指令的 imm12**（`addeq` 的立即数，8 位内任意值均可编码）：

| K | 字节 | 说明 |
|---|---|---|
| 6 | `06 c0 8c 02` | 最小可用 |
| **12（推荐）** | `0c c0 8c 02` | 覆盖到"一个距离名次 + 一个面积名次" |
| 18 | `12 c0 8c 02` | 强粘性，覆盖到 3 个距离名次 |
| 24 | `18 c0 8c 02` | 慎用，主体切换会明显迟滞 |

> 注意：整块替换时第 7 条必须与第 6/8 条保持顺序不变，否则标志位会算错。

**补丁后的循环（语义）**

```c
// prev = ctx->mainFaceIndex（覆盖前读出；首帧为 0）
for (int i = 0, off = 0; off != n*4; i++, off += 4) {
    int s = 3 * (areaRank[i] + 2 * distRank[i]);   // == 3*a + 6*d，数值不变
    if (off == prev*4) s += K;                      // ★ 上一帧主脸惩罚
    if (s >  best) bestIdx = i;                     // movhi
    if (s >= best) best  = s;                       // movhs
}
ctx->mainFaceIndex = bestIdx;
```

### 2.4 关于"额外 4 字节代码洞"

**本方案不需要代码洞**（2.2 的等价改写已经腾出空间）。但为了给其它补丁留后路，这里给出实测的洞清单：

扫描 `0x80020000`–`0x80500000` 全部 4 字节字：
- 连续 ≥8 字节的 `0xE1A00000(nop)`：**0 处**
- 连续 ≥8 字节的 `0x00000000`：**10 处**，全部位于函数入口前（链接器为 8 字节对齐插入的填充）；
  逐段核对其精确范围后，**没有一条 `B/BL` 跳进填充本身**（个别跳转落在紧邻的函数入口，不属于填充）。
  特别地，`0x804DDDF0` 的 36 字节 `0xE320F000(nop)` **不能当洞**（它是延时循环体，`0x804DDE1C` 的 `bne` 直接跳进去）。

**两个已验证可用的候选洞**

| 候选 | 范围 | 长度 | 上下文 | 安全性依据 |
|---|---|---|---|---|
| **H1（首选）** | `0x803E3288`–`0x803E3293` | **12 B（3 条指令）** | 前面是 double 常量 `0x3FA10CB2B1E1E995`，后面紧接函数 `0x803E3294`（`push {r4-r8,sb,sl,fp,lr}`） | 全镜像 `B/BL` 目标扫描：**无任何分支指向 `0x803E3288`–`0x803E3293`**；该 12 字节是链接器为 8 字节对齐插入的填充，不属于任何常量（前后常量各自 8 字节对齐） |
| **H2** | `0x803E1A18`–`0x803E1A1F` | **8 B（2 条指令）** | 前面是 double 常量 `0x3FB0000000000000`(0.0625)，后面紧接函数 `0x803E1A20` | 同上，无分支指向该 8 字节 |
| H3（备） | `0x80402990`–`0x80402997` | 8 B | 前一条是 `nop`+`bx lr`，后接 double `0x404E000000000000`(60.0) | 无分支指向；但紧邻常量池，插入代码后需重新确认没有代码用 `ldr rX,[pc,#..]` 读到该地址 |

另外一个"零成本"槽：**`0x801438C0`** —— 本补丁把循环回边从 `0x1438C0` 前移到 `0x1438BC`，原槽改写为 `nop`。
该区间（`0x143888`–`0x1438C3`）**除循环自身外没有任何分支跳入**，因此这个 4 字节是"补丁自带"的可用槽。

> 若要实现"3 条指令版"（`cmp` + `addeq` + 重新 `cmp ip,r0`），可以：把 `0x1438B0` 的冗余 `cmp` 用掉，
> 再借 H1 的 12 字节放剩余逻辑，用 `b`/`b` 两条指令进出（洞内净可用 4 条）。但**本报告不推荐**——
> 多的两次跳转会破坏流水、且在循环里每次迭代都付代价。

### 2.5 惩罚形式与 K 的取值

**形式**：`if (i == prevMainIdx) score += K`（对上一帧主脸**加分**，等价于对其它脸相对减分；因为最终只比大小，加减方向不影响结论）。

**打分公式与名次语义**

- `s = 3·areaRank + 6·distRank`，`areaRank, distRank ∈ [1, n]`，`n ≤ 10`
- `distRank` 越大 = 离画面中心越近；`areaRank` 越大 = 面积越大
- 取值范围 `9 … 9n`（`n=3` → 9..27；`n=10` → 9..90）
- 一个"面积名次" = 3 分；一个"距离名次" = 6 分

**K 的临界值推导**

设候选 A（本轮得分更高者）与上一帧主脸 P：

```
A 领先 Δ = 6·(dA − dP) + 3·(aA − aP)
加惩罚后 P 的分数 = sP + K
P 反超条件：K > Δ       （严格大于；取等时按原逻辑"并列取最小索引"，结果取决于索引顺序，必须避免）
```

| 场景 | Δ | 需要 K |
|---|---|---|
| A 与 P 名次完全相同（纯并列） | 0 | ≥1（K=6 足够） |
| A 比 P 大 1 个面积名次 | 3 | ≥4 |
| A 比 P 近 1 个距离名次（或大 2 个面积名次） | 6 | ≥7 |
| A 近 1 个距离名次 + 大 1 个面积名次 | 9 | ≥10 |
| A 近 2 个距离名次 | 12 | ≥13 |
| A 近 3 个距离名次 | 18 | ≥19 |

**实测算例（真实坐标，n=4，W=640×H=480，中心 (320,240)）**

| 脸 | 框 (x,y,w,h) | 面积 | 距中心² | distRank | areaRank | 原始分 |
|---|---|---|---|---|---|---|
| A | (280,200,80,80) | 6400 | 0 | 4 | 2 | **30** |
| P（上一帧主脸） | (200,200,200,200) | 40000 | 4000 | 3 | 4 | **30** |
| C | (0,0,100,100) | 10000 | 109000 | 1 | 3 | 15 |
| D | (500,300,80,80) | 6400 | 58400 | 2 | 1 | 15 |

- 无惩罚：A 与 P 同为 30，`movhi` 不改索引 → **A（索引 0）抢走主脸**。这就是"中心近但上一帧不是主脸"的典型翻脸。
- `K=6` → P=36 > 30 → **P 保住**（Δ=0，任何 K≥1 都够，这里只是演示）。

**Δ=6 的算例**（名次唯一，构造一个真正的 6 分差）：
A 又小又正（`areaRank=1`，`distRank=4`）→ `6·4+3·1 = 27`；
P 偏一点但面积排第 3（`areaRank=3`，`distRank=2`）→ `6·2+3·3 = 21`；
Δ = 6。
- `K=6` → P = 27，与 A **并列 27**：若 P 的索引大于 A，`movhi` 不触发，A 仍然胜出 → **K=6 不够**。
- `K=12` → P = 33 > 27 → **稳定保住**。

**Δ=9 的算例**（更贴近"中心近的同时还更大"）：
把上面的 A 换成 (160,160,240,240)：面积 57600（`areaRank=4`）、中心 (280,280) 距画面中心 3200（`distRank=4`）
→ `6·4+3·4 = 36`；P 仍 `distRank=3 / areaRank=3` → `18+9 = 27`；Δ = 9。
- `K=6` → P=33 < 36 → **A 仍胜**（惩罚无效）；
- `K=12` → P=39 > 36 → **P 保住**。这正是"K 必须 ≥ 10"那一档。

**建议值**

> **K = 12**（对应字节 `0c c0 8c 02`）。
>
> 理由：
> 1. 覆盖 Δ ≤ 11 的全部情形——即"更靠中心 + 最多一个面积名次"、"面积大两级"、"距离近一级且面积大一级"这些最常见的翻脸模式，且都留 3 分余量（不会退化成并列）。
> 2. 相对量级适中：对 `n=3` 的常见场景（总分 9..27），12 分 ≈ 44%，足以压过"中心近一级"(6)，但压不过"中心近两级"(12→需要 13)——**主体真正换人时仍会在 1 帧内切换**，不会锁死。
> 3. 若希望更强的身份粘性（例如长焦追人、目标常被遮挡），改 `K=18`（`12 c0 8c 02`）：覆盖到"近 3 个距离名次"，代价是主体切换最多迟 1 帧。
> 4. 不建议 K > 24：在 `n ≤ 4` 时 K 已接近总分跨度的一半，会出现"旧主体明显出画仍不切换"。
>
> **注意 K 与 FD 去抖的叠加**：`0x802F6DD4` 若同时改成 100–200 ms（丢失更快放弃），再叠 K=18，会出现"该丢不丢、该换不换"的双重迟滞。两项建议不要同时激进：先上 K=12 观察，再动去抖。

## 三、风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 首帧 `ctx+0x398` 若为未初始化垃圾值，可能等于某个合法索引 | 首帧主脸可能被误加 K | 该字段在同一函数每帧被覆盖；最坏只影响 1 帧。若介意，可在 `0x143888` 后加 `cmp sb, r8; movge sb, #-1`（需额外槽位） |
| R2 | 人脸索引每帧重排（检测器输出顺序变化） | 惩罚可能落在"编号相同但并非同一张脸"的对象上 | 这是本方案固有限制：只保证"索引级"粘性，不做 IoU/身份匹配。快速穿插场景下可能加剧误锁 |
| R3 | 打分公式被改写为 `3·(a+2d)` | 若某处依赖 `ip` 的中间值（`a*3`）——**已确认没有**，`ip` 在循环内只用于比较 | 无需处理；已用 20000 组随机用例验证 K=0 时输出完全一致 |
| R4 | 消除 `r1` 计数器 | 循环结束后 `r1` 的值与原实现不同。该值不会被本函数使用；调用点 `0x80143CA4` 是**尾跳**（先 `pop` 再 `b`），`r1` 属 caller-saved，按 AAPCS 不承担返回语义 | 无。另注：`r0` 在返回时恰好是 `best`（分数），本补丁在该值上会叠加 K——若有上层把该返回值当分数用，语义仍是"最高分"，只是基准平移了 K，不影响比较 |
| R5 | `0x801438C0` 被改成 nop | 若有外部分支跳到这里会执行 nop 后顺序落入 `str r7,[r6,#0x398]`，行为等价 | 已确认无外部分支指向该区间 |
| R6 | 静态分析未实机验证 | 编码正确 ≠ 运行正确（缓存一致性、指令/数据同步） | 刷机前先在 RAM 中跑；注意 Cortex-A 需要 `ICache` 失效序列 |
| R7 | 任务一的"改默认值"发生在 AF 管理器构造期 | 只有构造时执行一次；运行期被调试命令改过的值不会被重置，重启才恢复 | 若要持久化，改初值；要临时验证，用调试命令 `af multi algo tracking <ng> <small> <ok>` |
| R8 | `0x8034EA08` 的旁路会覆盖三个阈值（`ng=0x1E8480, ok=0, small=0`） | 当 `GAF[3] & 0x20 != 0` 或 `GAF[0x5c] > 3` 时走该分支，改默认值不生效 | 若要全模式生效，需同时处理该分支 |

## 四、未解项

1. **`small` 的确切消费分支未 100% 钉死。**
   `GAF+0x48 → tracker+0x158` 的拷贝链已确认；`+0x158` 在 `0x8035E0A0` 被读出后与 `#0x2C(44)` 比较，与"小目标抖动上限 4"的语义不吻合（疑似该处使用的是另一个重载字段，或含比例缩放）。
   另有一条 `0x8034D5FC`（`ldr r2,[r0,#0x164]; cmp r2,#4; bgt`）把计数器与**硬编码 4** 比较，怀疑是同一逻辑的另一份内联实现。
   → 结论不受影响（初值位置已确证），但"small 生效点"仍列为待验证。
2. **`0x801438D8` 与 `0x80143740` 的函数关系未查。**
   两者 prologue 完全相同、都读 `+0x39c`，调用点分别在 `0x80143CA4`（尾跳）与 `0x80143E60`。疑似"单区域 / 多区域"两套主脸选择。本次只补了 `0x80143740`；若实际走的是 `0x801438D8`，惩罚不会生效——**上机第一步应先确认走哪条**（在 `0x801438C4` 打日志或断点即可）。
3. **`0x81550220` 与 `0x81550408` 的结构关系未澄清。**
   `0x81550220+0x22C == 0x81550408+0x44` 说明二者是同一块内存的不同基址（相差 `0x1E8`）。究竟 `GAF` 是某个大对象的内嵌子结构，还是两个独立全局恰好相邻，未做进一步确认。对本补丁无影响。
4. **`0x802F6CFC/0x802F6DD4`（FD 去抖）与本次惩罚的联合调参未做实测。** 建议 K 与去抖分两轮上。
5. **未验证 `0x1438A0/0x1438B0` 两条 `cmp` 在其它编译单元（如 `0x801438D8`）里是否同样冗余。** 若后续要把同样的补丁复制到 `0x801438D8`，需重新走一遍本报告 2.2 的等价性验证。
