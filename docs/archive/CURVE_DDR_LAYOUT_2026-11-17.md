## 0. 一句话结论

写表函数 `0x8049E4D4` 是**纯平铺 108 字拷贝**（`dst[i] = src[i]`，i=0..107），它不做任何通道/节点重排。
因此 108 字的结构完全由生产者 `0x8038F90C` 决定，实测（符号执行）结果是：

> **432 字节 = 2 个 216 字节子块；每个子块 = 108 个 u16 = `X[22] + Y[22] + A[21] + B[21] + 22×0`。**
> **不是 4 通道 × 27 点，也不是 4 通道 × 19 点 + 32 字。**

通道维度不在这 108 字里：每个通道是**独立对象实例**，各自调用一次计算 + 一次写表（`r0` = 实例号）。

## 1. 调用链（L1）

```
obj(通道实例) ──> 0x8038F90C(obj, arg)          ; 计算 + 打包 432B 到栈上 sp+0x1F8
                0x80390A18  bl 0x8017CF88(handle, buf)
                             └─ 0x8017CF88: 上报 + 尾分支
```

关键点：`0x8049E4D4` 在全镜像里**没有任何 BL 调用点**（`findbl.py` 扫描结果为空），唯一静态入口是 `0x8017CFCC` 的尾分支；`0x8017CF88` 的调用者是 `0x801377B4`、`0x8038F868`、`0x80390A18`。

```
0x8017CFCC  b    #0x8049e4d4       ; <<< 尾分支进入写表
```

## 2. 写表函数 0x8049E4D4：确认是平铺拷贝（L1）

```
0x8049E4D4  cmp  r1, #0
0x8049E4D8  push {r3, r4, r5, lr}
0x8049E4DC  ldrne r5, [pc, #0x48]     ; = 0x813EBF50（实例基址指针数组，运行期 RAM）
0x8049E4E0  movne r3, #0
0x8049E4E4  beq  #0x8049e514
0x8049E4E8  asr  r4, r3, #2           ; r4 = 字节偏移 / 4 = 字索引 i
0x8049E4EC  add  r2, r3, #0x1f00
0x8049E4F0  ldr  ip, [r5, r0, lsl #2] ; ip = base[instance]
0x8049E4F4  ldr  r4, [r1, r4, lsl #2] ; r4 = src[i]  ← 源缓冲按字线性取
0x8049E4F8  add  r3, r3, #4
0x8049E4FC  add  r2, r2, #0x28        ; r2 = 0x1F28 + 字节偏移
0x8049E500  cmp  r3, #0x1b0           ; 0x1B0 = 432
0x8049E504  str  r4, [r2, ip]         ; dst = base[instance] + 0x1F28 + 4*i
0x8049E508  bne  #0x8049e4e8
0x8049E50C  mov  r0, #0
0x8049E510  pop  {r3, r4, r5, pc}
```

结论：
- 目的地址 = `base[instance] + 0x1F28 + 4*i`，i = 0..107；`base[]` 取自 `0x813EBF50`（运行期，静态读不到 → 表地址本身是 **L3**）。
- 源 == 目的，一一对应，**无重排、无步长、无通道拆分**。
- 旁证：`0x1F28 + 0x1B0 = 0x20D8`，正好是兄弟函数 `0x8049E538` 写的控制块起点 `base+0x20C0+0x18`，两块首尾相接不重叠（L1）。

## 3. 432 字节缓冲的生产者 0x8038F90C（函数体 0x8038F90C–0x80390A38，约 4396 字节）

### 3.1 函数内四个 19 点数组的来源（L1）

对象构造器 `0x8038DA5C`（vtable = `0x8062F6B0`）把 4 个 76 字节（19×u32）默认表 memcpy 到对象里：

```
0x8038DAA4  add  r0, r4, #0xe40        ; +0xE40
0x8038DAA8  ldr  r1, [pc, #0x5c]       ; = 0x8062F6D0  (X19 非均匀网格)
0x8038DAB4  add  r0, r4, #0xe80
0x8038DAC0  add  r0, r0, #0xc          ; +0xE8C
0x8038DAB8  ldr  r1, [pc, #0x50]       ; = 0x8062F71C  (Y19 默认曲线)
0x8038DAC8  add  r0, r4, #0xed0
0x8038DAD4  add  r0, r0, #0xc          ; +0xEDC
0x8038DACC  ldr  r1, [pc, #0x38]       ; = 0x8062F6D0
0x8038DADC  add  r0, r4, #0xf20
0x8038DAE8  add  r0, r0, #8            ; +0xF28
0x8038DAE0  ldr  r1, [pc, #0x28]       ; = 0x8062F71C
```

即 `+0xE40/+0xE8C` = (X,Y) 计算输出，`+0xEDC/+0xF28` = (X,Y) 目标节点，与外部报告一致（L1）。

## 4. 108 字 / 216 个 u16 的完整映射（L1，符号执行逐条核对）

打包代码把 216 个 16 位值写进 `sp+0x1F8 .. sp+0x3A7`，**216 个偏移全部覆盖、无重复写**（只有每块最后一个 u16 找不到写点，见 §8）。写点覆盖关系由 `emu2.py` 从 `0x8038FCA8` 到 `0x80390A18` 逐条模拟得到。

### 4.1 公式（可直接实现）

设缓冲区字节偏移 `off = 0..431`：

```
blk  = off // 216           # 0 = 前半块(字节 0..215)，1 = 后半块(字节 216..431)
b    = off % 216            # 块内字节偏移
u    = b // 2               # 块内 u16 序号 0..107
hi16 = (off % 4) == 2       # 同一个 32 位字里，偶地址=低半字，奇地址=高半字

u <= 21        -> X[u]           # 22 个：x 坐标
22 <= u <= 43  -> Y[u-22]        # 22 个：y 值
44 <= u <= 64  -> A[u-44]        # 21 个：段系数 A
65 <= u <= 85  -> B[u-65]        # 21 个：段系数 B
86 <= u <= 107 -> 0              # 22 个 u16 恒 0
```

### 4.2 32 位字级映射（块内字索引 w = 0..53，块 1 再加 54）

| 字 w | 低半字 | 高半字 | 说明 |
|---|---|---|---|
|0|X[0]|X[1]|X[0..2] = 暗电平常数 -1024/-439/-146 |
|1|X[2]|X[3]|X[3] = C0 曲线第 1 点 |
|2..10|X[2w]|X[2w+1]|X[4..21]，X[21] 被强制为 0x3FFF |
|11|Y[0]|Y[1]|Y[0..2] = 由第一段反向外插 |
|12..21|Y[2w-22]|Y[2w-21]|Y[3..21] = 19 点曲线（块 0 已过二次曲线，块 1 未过）|
|22..31|A[2w-44]|A[2w-43]|A[0..19]|
|32|A[20]|B[0]|跨数组边界 |
|33..42|B[2w-65]|B[2w-64]|B[1..20]|
|43..53|0|0|22 个 u16 全 0 |

对应 DDR 绝对地址：`base[instance] + 0x1F28 + 4*w`（块 0）、`+ 4*(w+54)`（块 1）。**整块 108 字 = 2 个子块 × 54 字**。

### 4.3 位宽（L1）

```
0x8038FCB8  bfi  sl, sb, #0, #0xf     ; X 写低 15 位（bit15 保留原值，本次执行恒 0）
0x8038FE54  bfi  sl, sb, #0, #0xb     ; Y 写低 11 位（bit15..11 保留原值）
0x8038FF94  ldr  r3, [sp, #0x4c] ...  ; A/B 直接 strh 低 16 位，无掩码
0x803901CC  bfc  r4, #0, #0x10        ; 填充区清零
```

X 用 15 位是有意义的：`-1024` 按 15 位补码 = `0x7C00`，与 `0x3FFF`(16383) 正好同一字段（L1 算术，L2 语义）。
Y 只留 11 位 → 负数会被截断成 `v & 0x7FF`；只有当 `Y[0..2]` 非负时才安全（见 §9 未解项）。

## 5. 19 → 108 的重采样：没有 27 点插值（L1）

1. **不存在 27 点**。整个函数里没有任何 `#0x1b` / 27 次循环；`#0x1b` 只出现在别处无关代码。19 → 硬件表的真实路径是 **19 → 22 节点 → 21 段**：
   - `sp+0x148` 起 44 个字 = 22 个 X，`sp+0x1A0` 起 44 个字 = 22 个 Y（`0x1A0-0x148 = 0x58 = 22*4`）。
   - 19 点位于 **索引 3..21**（`sp+0x154` 与 `sp+0x1AC` 就是 22 点数组的第 3 项）；前面 3 点是被拼上去的"黑外区"节点。
   - `0x8038DCE0` 的第 7 参 = `0x16`(22)：`0x8038FC84  mov r3, #0x16; str r3, [sp, #8]`，它对 22 个节点算 21 段系数（A/B/C，`0xF4-0x4C = 0x54 = 21*4`）。
2. **x 网格不是均匀网格重建，而是沿用非均匀 X19**：`0x8038FB0C` 的循环只做"尾部修正"——从尾部往前找最后一个 `X <= 0x3FFE` 的点，再从该点起按 `步长 = (0x3FC0 - X_prev + 0x3F) / 剩余段数` 补齐到 `0x3FFF`：
   ```
   0x8038FAE4  movw r1, #0x3ffe          ; 截止阈值
   0x8038FB14  ldr  fp, [r3]             ; X[k]
   0x8038FB1C  cmp  fp, r1
   0x8038FB28  ble  #0x80390b68          ; 找到 → 转去正常路径
   0x80390B68  ldr  r8, [sp, #0x34]      ; X 数组基址
   0x80390B80  rsb  sl, r7, #0x12        ; 剩余段数 = 18 - k
   0x80390B94  str  sl, [sp, #0x20]
   0x80390B98  b    #0x8038fb5c
   ...
   0x8038FBA0  rsb  r8, fp, #0x3fc0      ; 0x3FC0 - X_prev
   0x8038FBA8  add  r8, r8, #0x3f        ; +0x3F
   0x8038FBAC  udiv r8, r8, r2           ; / 剩余段数
   0x8038FBDC  add  fp, r7, fp           ; X = X_prev + step*...
   0x8038FBE4  ldr  r0, [sb, #-0x1fc]    ; 同一轮还会为新 X 重插值 Y
   0x8038FBE8  str  fp, [r8, #-0x254]    ; 写 sp+0x154+4k (X)
   0x8038FC24  str  r0, [r8, #-0x1fc]    ; 写 sp+0x1AC+4k (Y)
   ```
   对默认 X19（最大 16383 > 0x3FFE）→ 命中 k=20，只重写 `X[21] = 0x3FFF`，其余保持原非均匀值。
   **⇒ 非均匀网格（0/32/74/…/15872）原样进入硬件表；不是"固定均匀网格"。**
3. **段内插值由硬件用 A/B 做**（不是软件先插成 27 点）。A/B 各 21 个，一 一对应 21 段：
   ```
   0x8038DF7C  lsl  r8, r8, #0xd         ; 整数部分 <<13
   0x8038DF80  addlt r7, r7, #0x2000     ; 负小数补 2^13（借位）
   0x8038DF88  add  r7, r8, r7           ; B[i] = (int<<13) + frac  → Q13 定点
   0x8038DF74  str  r0, [r1, r4]         ; A[i] = 整数部分
   0x8038DF94  str  r3, [r0, r4]         ; C[i] ≡ 0（str r3,#0）
   ```
   `B` 明确是 **Q13 定点**（L1）。A 是整数部分（L2）。二者合成 y 的公式未在镜像里直接出现 → 归入未解项。

## 6. X 坐标的去向（回答 Q3）

- **写进去了**：每个 216 字节子块的头 22 个 u16（字节 `+0x000..+0x02B`），值 = `X[0..21]`，15 位宽。
  - `X[0..2]` = 常数 `-1024 / -439 / -146`（来自 `0x8062F898`，在 `0x8038FAE8` 存入 `sp+0x148..0x150`，前缀为暗电平/黑外区节点）。
  - `X[3..21]` = C0 曲线的 19 个 x；尾部修正保证 `X[21] = 0x3FFF`。
- **不是"只用于计算时定位"**：X 与 Y/A/B 一起进 DDR 表（L1）。
- 反汇编依据：
  ```
  0x8038FCA8  add  r1, sp, #0x200
  0x8038FCA8  ldrh sl, [r1, #0xd0]      ; 读 OUT[0xD8]
  0x8038FCB0  ldr  sb, [sp, #0x148]     ; X[0]
  0x8038FCB8  bfi  sl, sb, #0, #0xf
  0x8038FD44  strh sl, [sb, #0xd0]      ; 写 OUT[0xD8]
  ```

## 7. 0x803C55B8 是什么（回答 Q4）

**不是"从对象取某通道的 19 点"**，而是一个 **32 位打包位域取数器**（`get_bitfield(obj, word, idx)`）：

```
0x803C55B8  push {r3, r4, r5, lr}
0x803C55BC  ldr  r3, [r0, #0x1c]        ; 字段个数
0x803C55C0  cmp  r3, r2
0x803C55C4  ble  #0x803c5610            ; 越界 → 断言
0x803C55C8  ldr  r3, [r0, #0x18]        ; 字段宽度数组
0x803C55D0  ldr  r0, [r3, r2, lsl #2]   ; width = widths[idx]
0x803C55D4  mvn  r5, #0
0x803C55DC  mvn  r5, r5, lsl r0         ; mask = (1<<width)-1
0x803C55E0  ble  #0x803c5624            ; idx<=0 → shift 走特殊分支
0x803C55E4  add  r4, r3, r2
0x803C55E8  mov  r2, #0
0x803C55EC  ldr  ip, [r3], #4           ; 累加前 idx 个字段宽度
0x803C55F0  cmp  r3, r4
0x803C55F4  add  r2, r2, ip
0x803C55F8  bne  #0x803c55ec
0x803C55FC  rsb  r2, r2, #0x20
0x803C5600  rsb  r2, r0, r2             ; shift = 32 - sum(prev) - width
0x803C5604  and  r0, r1, r5, lsl r2
0x803C5608  lsr  r0, r0, r2             ; (word >> shift) & mask   ← MSB-first 打包
0x803C560C  pop  {r3, r4, r5, pc}
```

- 函数体 **0x54 字节 / 21 条指令**（0x803C55B8–0x803C560C）。
- 内部循环边界 = **调用参数 idx**（即通道号 0..3，最多 3 次累加），不是 19 也不是 27。
- 在 `0x8038F90C` 里被连调 4 次（`r2 = 0,1,2,3`）取出配置字的 4 个字段；`field0` 决定数据源分支（`cmp r7,#4`），`field1/field2` 作为 7 字/项系数表的索引（`rsb r6,r6,r6,lsl #3` = ×7，`0x8062F8C0 + 28*field`）。
- 该地址确实作为函数指针出现在 `0x8062F6C8`（同表还含 `0x8038F90C`、`0x8038DA20` 等，是类 vtable 段）。

## 8. 两块子表为什么看起来"一样"、结尾两个 u16 为什么没写

- 符号执行时我把步骤⑨的二次曲线循环跳过了（`0x80390218 → 0x80390240`），所以模拟结果里两块一致。**真实运行中两块不同**：
  - 块 1（字节 216..431）= 用目标曲线（`obj+0xEDC/0xF28`）算出的 Y；
  - 块 0（字节 0..215）= 同一批 Y 再经 `0x80390218–0x8039023C` 的固定 17 点曲线变换后的 Y，并重算 A/B。
  ```
  0x803901D0  add  r7, sp, #0x1ac        ; 起点 = Y[3]
  0x80390208  add  r5, sp, #0x1f8        ; 终点 = Y 末尾
  ```

## 9. 端点处理（回答 Q5）

| 项 | 结论 | 证据 |

## 10. 108 字结构：候选排序与证据强度

| 候选 | 判定 | 强度 |
|---|---|---|
|A. `2 × (X22 + Y22 + A21 + B21 + 22×0)`（均为 u16）|**成立**：216 个 u16 的写点全部定位，符号执行无遗漏、无冲突|**L1**（指令级）＋L2（A/B 语义）|
|B. 4 通道 × 27 点|**否**。写表函数是平铺 108 字；生产者里没有任何 27 次循环，也没有按 27 分组的步长|L1（排除）|
|C. 4 通道 × 19 点 + 32 字其它|**否**。19 点只占 `X[3..21]/Y[3..21]`，其余是黑外区节点与段系数|L1（排除）|
|D. 交错排列|**部分成立但表述不准**：不存在"通道×节点"交错；存在的是"同一 32 位字含两个 u16 字段"的打包（低半字/高半字，跨数组边界：字 32 = {A[20], B[0]}）|L1|

通道维度的正确理解（L2）：4 个通道是 4 个对象实例，各自算一次、各自写一次表（`base[instance] + 0x1F28`）。`0x8038F90C` 里出现的 4 次 `0x803C55B8` 只是取**同一对象的配置字里的 4 个字段**，不是 4 个通道的数据。

## 11. 未解项清单

1. **A/B 的合成公式**（L3）。已知 B = Q13 定点（`0x8038DF7C/0x8038DF80/0x8038DF88`）、A = 整数部分、C ≡ 0；是 `y = (A*x + B) >> 13` 还是 `y = A + (B*(x - X[i])) >> 13`，镜像里没有直接体现（HW 侧行为）。
2. **填充区 22 个 u16 的语义**（L2）。恒 0；数量正好 = X/Y 长度，也可能是"从未使用的第三系数数组 C(21) + 1 个对齐"，无法从静态代码区分。
3. **每块最后一个 u16（0xD6 / 0x1AE）无写点**（L3）。
4. **`base[instance]` 的真实值**（L3）。`0x813EBF50` 在运行期 RAM，静态为空；此前推测 bank1 = 0xBB71D300，未验证。
5. **两块子表的用途差异**（L3）。静态可证"块 0 = 块 1 的 Y 再过一次 17 点固定曲线、并重算 A/B"，但硬件把这两块当"两个通道 / 两个 bank / 两次采样"中的哪一种，需要写寄存器后回读 DDR。
6. **legacy 分支（`field0 <= 4`）**（L3）。此时数据源 = `0x8062F6F8 + 76*field0` / `0x8062F744 + 76*field0`，与默认 X/Y 表错位重叠，静态看不出其自洽性；推测是另一套 12 点/旧格式兼容路径，需实机。
7. **Y[0..2] 的 11 位截断**（L3）。外插可能为负（最低到 -1023），而 `bfi #0,#0xb` 只保留低 11 位 → 会出现 `v & 0x7FF`。是否真会出现负值，取决于 C0 首点 Y 与 X[3]。
8. **X/Y 条目的保留位**（L3）。X 用 `bfi #0,#15`、Y 用 `bfi #0,#11`，高位是"读-改-写"保留下来的栈内容；我按 0 处理。若实机读到非 0 高位，说明别处有预清零（未见）。

## 附：108 字掩码实证（2026-11-17 补，解掉块布局冲突）

同源外部仓库 `_ext_nx500srw/work/r10j-frame-flow/core/src/rtos_gamma.inc` 的
`gt_apply()` 给出了**实际使用的掩码规则**，这是第三方独立实现，与我们的静态推断互相印证：

```c
for (unsigned i = 0; i < 108; i++) {
    unsigned j = i % 54;                       /* ← 108 = 2 组 × 54 字 */
    uint32_t mask = j < 11  ? 0x7FFF7FFF       /* 15 位 ×2 */
                  : j < 22  ? 0x07FF07FF       /* 11 位 ×2 */
                  : j == 53 ? 0x0000FFFF       /* 仅低半字 */
                  :           0xFFFFFFFF;
    target[i] = (DDR[i] & mask) | (saved[i] & ~mask);
}
```

### 结论：每 54 字 = 107 个 u16 字段 + 1 个填充

| 区段 | 字数 | 字段数 | 位宽 | 掩码 |
|---|---|---|---|---|
| X | 11 | 22 | 15 bit | `0x7FFF7FFF` |
| Y | 11 | 22 | 11 bit | `0x07FF07FF` |
| A / B / C | 31 | 21+21+21 = 63 | 16 bit | `0xFFFFFFFF` |
| 尾 | 1（`j==53`） | 1（仅低半字） | 16 bit | `0x0000FFFF` |

**⇒ 上一轮"X[22]+Y[22]+A[21]+B[21]+22×0"的结论作废**：末尾那 22 个"零"实际是
**A[21] / B[21] / C[21] 三个数组**，不是填充。`C` 恒 0 但**占位、必须写**。

X 用 15 位、Y 用 11 位的位宽也解释了为什么 C0 的 X 上限是 16383（14 位有效）而 Y 是 1023（10 位有效）——
编码各留 1 位余量。

### 硬件接受的输入域（来自 `gt_request_valid`，硬约束）

```c
X[0] == 0            X[18] == 16383       /* 端点钉死 */
Y[0] <= 0            Y[18] == 1023        /* 黑白点钉死 */
X 严格递增            Y 单调不减           /* 不允许任何反向 */
其余 17 点：X∈[0,16383]、Y∈[-1024,1023]
```

`Y[-1024,1023]` 允许负值（下探到 -1024），比 C0 的 0–1023 宽 —— 负 Y 用于趾部压黑。

### 对象构造（`gt_apply` 里的 vtable 与参数组）

```c
o[0] = 0x8062F6B0;  o[2]=metadata; o[3]=parent; o[6]=widths; o[7]=5;
*(uint32_t*)metadata = 2;  *(uint32_t*)(parent+12) = 256;
widths[5] = {3, 5, 4, 13, 2};    /* 合计 27 */
```

即计算函数 `0x8038F90C` 需要的是一个 **vtable 对象 + 5 组宽度 3/5/4/13/2 的参数**，
而不是裸数组。这是自建装载路径时最容易漏的一环。

### 装载是「两段式」

1. `obj+0xEDC[19] = X`，`obj+0xF28[19] = Y`
2. 调 `0x8038F90C(obj, 0xAA000000, 0)`，然后**回读** `obj+0xE40[19]` 与 `obj+0xE8C[19]` 校验
3. 只有回读一致才拼 108 字并调 `0x8049E4D4`

`bank0`（`0xBB71D228`，与 bank1 差 0x2000）**全程只哈希不写**，用来证明没有误伤另一 bank。
