## 1. 基线与门槛（三个数不许混用）

| 量 | 值 | 性质 |
|---|---|---|
| 冷转码准入线 | `MemFree + Cached ≥ 40960 KB` | **门槛**，启动前判一次，不足即降级 |
| 1024 px 单次转码峰值 RSS | ~31 MiB | 资源预算 |
| 11-16 并发基准整机低点 | 55.3 MiB | **对照记录**，不是门槛，也不是目标 |
| 1024 px 冷转码单张 | 6.39 s | 待优化基线 |
| 20 图网格直切 | p50 150 / p95 220 ms | 现有基线 |

FilmLab 一律分三档报：**空缓存全量换配方 / 差量换配方 / 重选同一配方**（552 / 455 / 157 ms 分别对应，不可合并成"一个数"）。

## 2. P0-A 成片完整性（先做，决定 P0 能否放行）

三轮，同卡、同码率、同机位、同录制时长；每轮记 `MemFree+Cached` 时间序列。

| 轮次 | 负载 | 目的 |
|---|---|---|
| A0 空载 | 只录，不碰相册 | 成片基准：文件头尾、时长、音画连续 |
| A1 基线 | 录像中**强行**触发 1 次 1024 px 冷转码 + 20 图网格 | 量干扰有多大（这是破坏性实验，见护栏） |
| A2 候选 | 录像中提交同一冷请求 | 验降级/延后是否生效 |

**A1 护栏（必须，否则可能拔电池）**：转码进程起前先记 `MemFree+Cached`；低于 40 MiB 立即放弃该轮；全程 1 s 粒度采样内存；出现 camera daemon 消失立即停录并记录现场。`thumb-cache.sh` 注释已写明此处 OOM 会拉挂相机守护进程、需拔电池恢复。

**A2 判据**：请求返回"降级/排队"而非"已完成"；`ps` 中无 `convert` 进程；`MemFree+Cached` 不跌破 40 MiB；停录收尾确认后同一请求可重试并成功。

**成片判据（A0/A1/A2 同一套）**：
1. PC 端完整解码无错误，无花屏、无截断；
2. 时长与录制时长偏差在 1 帧内；
3. 音视频轨都存在，音画同步无明显漂移；
4. 文件尾 `moov` 完整（停录未被打断）；
5. 逐段抽帧（头/每 10 s/尾）字节比对 A0，确认无重复段或丢段。

## 3. P0-B 收尾状态机与停录时间线

### 3.1 采样时间线（这是四态定义的唯一依据）

按 100 ms 粒度记录，至少 5 轮：

```
按 REC → 首个可写 MP4 fd 出现 → 停录键 → fd 消失 → 收尾确认 → 文件大小稳定 → 可读
```

每轮落一份 `{t, pid, fd 列表, 可写标志, 文件大小, MemFree+Cached}`。

### 3.2 四个必须覆盖的边界样本

| 样本 | 场景 | 期望 |
|---|---|---|
| B1 | **刚开录、fd 尚未出现**（REC 后 <1 s） | 判为"非待机"，重任务不放行（现状：FD 扫描会判成待机 ⇒ 需修） |
| B2 | **fd 已消失但收尾未确认** | 仍判"正在收尾"，不放行（这是最危险的一段） |
| B3 | 探测失败（`pidof` 空 / fd 读不到 / 非 1 号模式） | 判"未知状态"，重任务不放行 |
| B4 | 休眠唤醒 / 卡拔插后状态过期 | 强制重扫，不复用旧判定 |

### 3.3 通过条件

- `录制` / `正在收尾` / `未知状态` 三态下：零批量转码、零预热、零非必要参数写入（用 `ps` + 转码日志 + SD 写入计数三重取证）；
- 放行只认**收尾确认**，不认"无 fd"；
- 状态切换延迟有实测数字（不给上限承诺，先记录）；
- 任何一态下相册仍可返回已缓存缩略图，且不因拒绝而报错给用户。

## 4. P0-C 恢复路径：现状核对与失败注入

### 4.1 现状（不是设计）

| 环节 | 现状 | 风险 |
|---|---|---|
| 相册模块更新 | 逐文件 `cp -f` 覆盖，无版本目录、无 rename 切换、无就绪回滚 | 中途断电 = 半新半旧，前端引用不存在的 JS |
| TC 恢复 | `cleanup()` 仅在 `NEEDS_RESTORE=1` 时写回 STOCK 并逐项回读；回读不过则 `RESTORED=0` + 退出码 4 | 恢复失败有信号，但**不会自动重试** |
| LUT 指针表恢复 | `nx_lutptr.arm restore ... \|\| true` | 失败无提示，后面照样还 View4/Still6 ⇒ 取景原厂、录像仍指 A18 的混合态 |
| LUT 备份污染 | `begin` 调 `sh $0 off` 后**不检查退出码**就 `slot read` 备份 | 若 off 失败，备份下来的 A18 就是"已经被改过的表"，此后 `off` 会把它当原厂还原 |

### 4.2 失败注入（每例必须回读确认"恢复到了什么状态"，不看退出码）

1. 删 `lutptr.bak` 后 `off` → 期望：明确报 `VIDEOPTR not restored`，退出码非 0；实测结果记录。
2. `a18_orig.bin` 置 0 字节后 `off` → 期望：走 `$TD/factory/a18_orig.bin` 回退且回读全等。
3. `begin` 时预置"残留 ready + 指针表已改" → 期望：先真还原再备份，备份内容 ≠ 被改表。
4. `tc.sh` 写入中途 `kill -9` → 期望：重跑 `tc_verify` 能判出非 stock 并给出可恢复路径。
5. `update_nxrc.sh` 覆盖到一半断电 → 期望：至少能识别"半新半旧"并回到一致版本。

### 4.3 通过条件

- 五个注入例全部产生**可判定的状态输出**（不是静默）；
- 每个例子的回读结果写入日志；
- `begin` 的备份污染路径被堵住（off 非 0 即 `die`，不备份）。

## 5. 不放行条件（任一命中即阻塞）

- A1 出现成片不可完整解码，且无法归因到具体资源争抢点；
- B1/B2 中任一被误判为"待机"并实际放行了重任务；
- 4.2 任一注入例出现静默成功（退出码 0 但状态不对）；
- 任何一轮出现 camera daemon 退出。
